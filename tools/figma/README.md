# Dreadnought — локальный плагин Figma

Плагин обновляет токены и стили из текущего исходного кода, исправляет созданные Button, текстовый Input, Card и добавляет следующую группу компонентов в файле Diploma, страница **1 module**. Другие страницы не изменяет. Вайрфреймы не создаёт.

## Запуск

1. В настольной Figma откройте Diploma.
2. Откройте **Plugins → Development → Import plugin from manifest…**.
3. Выберите `output/figma-plugin/manifest.json` из репозитория.
4. Запустите **Plugins → Development → Dreadnought — Local Sync**.
5. Нажмите **Обновить и исправить**.
6. Сохраните отчёт и PNG образцов кнопками плагина. Проверьте прозрачность disabled/loading, контраст иконок, контуры фокуса и перенос длинного текста Card.

Для добавления компонентов нажмите **Добавить компоненты библиотеки**. Сначала выполняется обычная синхронизация, затем создаются только отсутствующие наборы и стенды с экземплярами. Первая группа — 10 наборов:

| Компонент     | Варианты                                                                      |
| ------------- | ----------------------------------------------------------------------------- |
| Mark          | circle / square, 6px                                                          |
| Checkbox      | checked false / true / mixed × default / focused / invalid / disabled         |
| Radio         | checked false / true × default / focused / invalid / disabled                 |
| Switch        | checked false / true × default / focused / invalid / disabled / loading       |
| Select        | 3 набора оформления; в каждом controlSize × empty / single / multiple × state |
| Select Option | default / active / selected / disabled                                        |
| Select Popup  | options / loading / empty, полупрозрачная поверхность и background blur       |
| Badge         | solid / outline / ghosted × none / mark / icon                                |

Всего в группе 120 вариантов. Встроены SVG из установленного Ant Design, а не нарисованные заново иконки. Текст и доступные слоты редактируются свойствами экземпляров; группы Checkbox/Radio собираются из экземпляров. Badge пока только standalone, без overlay/count-композиции. Group-пропсы, поиск, виртуализация и клавиатурная логика Select не исполняются в Figma. Popup — отдельный компонент для макета, без автоматического открытия. Loading — статичный образец, без анимации.

Следующая группа — **Alert, Toast и Loader**: ещё 4 набора, 21 вариант:

| Компонент      | Варианты                                                |
| -------------- | ------------------------------------------------------- |
| Alert          | info / success / warning / error × outlined / filled    |
| Toast          | info / success / warning / error                        |
| Loader         | small / default / large (16 / 32 / 48px в текущей теме) |
| Loader Overlay | loading true / false × small / default / large          |

Текст, описание, закрытие и иконка уведомлений управляются свойствами экземпляра. Alert по умолчанию без иконки и закрытия, как в коде; стенд включает их. Подпись Loader по умолчанию скрыта; стенд показывает её. Overlay содержит настоящий вложенный экземпляр Loader и демонстрационную область children 280×112, а не отдельную копию спиннера. Подпись вложенного Loader меняется через свойства этого экземпляра.

Цвет filled Alert вычисляется из исходного `color-mix(... 14%, ...)` и привязывается к четырём COLOR-переменным в `Figma resolved`; кнопка добавления компонентов обновляет их без дублей. Иконка Toast и small Loader размером `1em` переведены в px для стандартного текстового контекста темы (16px). Toast сохраняет обычную поверхность из текущего кода, без придуманного blur.

Это статичные компоненты. В этой группе ещё не перенесены action-слоты уведомлений, ToastViewport с шестью положениями, таймеры, delay и пользовательский индикатор Loader. Они не изображены как работающий функционал Figma.

Повторное добавление сохраняет существующие наборы, их ID и правки. Если набор с таким именем имеет другую матрицу вариантов, операция останавливается без его удаления. При ошибке во время создания одного нового набора удаляются только временные узлы этой попытки. Уже завершённые наборы сохраняются. Существующие старые наборы не пересоздаются.

Если Figma требует собственный ID для development-плагина, создайте его через **Development → New plugin** и замените поле `id` в сгенерированном `manifest.json` выданным ID. Публиковать плагин не нужно.

## Обновление после изменений библиотеки

Из корня репозитория:

```sh
node tools/figma/build.mjs
```

Затем закройте окно работающего плагина и снова запустите его: код уже обновлён, повторный импорт manifest не нужен. ID development-плагина при сборке сохраняется. Переменные и стили обновляются по коллекции и имени, их ID сохраняются. Другие режимы коллекций не перезаписываются. Конфликт типа приводит к ошибке, а не удалению переменной. Переменные с одинаковым CSS-синтаксисом в коллекции `Figma resolved` не подменяют исходные токены.

Нет новых зависимостей: сборка использует уже установленные PostCSS и esbuild. Сеть запрещена в manifest; API-ключи и MCP не нужны.

## Границы переноса

- `rem` → px при базовом размере 16px.
- `em`, проценты и составные CSS-значения остаются строками с исходной записью.
- Отступ Card, вычисляемый через `calc`, представлен отдельным числом Figma resolved. После изменения исходного отступа требуется повторная синхронизация.
- Opacity проверяется по фактическому значению узла. При процентной шкале Figma создаётся вычисляемая переменная; CSS-значение остаётся в шкале 0–1.
- Изменения не транзакционные: если Figma сообщает ошибку, ранее применённые шаги могли сохраниться. Повторный запуск не создаёт дубли переменных и стилей. Ошибка и отчёт не заменяют визуальную проверку.
- Обычная синхронизация исправляет существующие Button, Input и Card; отсутствующие наборы перечисляются в предупреждениях. Отдельная кнопка добавляет описанные выше группы.
- Плагин не удаляет пользовательские узлы, не отсоединяет экземпляры и не сбрасывает текстовые свойства.

## Проверки

```sh
node --test tools/figma/sync.test.mjs tools/figma/components.test.mjs
```

Тесты используют модель API, не запущенную Figma. Проверку реального отображения нужно выполнить после запуска плагина.
