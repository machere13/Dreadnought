# План: общий каталог, поиск и RAG документации

Статус: первый этап реализован — генератор каталога Button и Input. Подключение сайта, общий поиск и RAG остаются следующими этапами.

**Результат:** машиночитаемый каталог становится общим источником API для второго AI-контура, сайта и RAG. Руководства дополняют его. Существующие Astro-маршруты сохраняются.

**Спецификация:** [browser-rag-design](../specs/2026-09-26-browser-rag-design.md).
**Общая архитектура:** [AI-каталог](../../architecture.md#8-ai-каталог-и-graphify).

## Текущее состояние

- `apps/docs` уже содержит Astro-сайт с React-компонентами, руководствами и страницами компонентов.
- `apps/docs/src/components/DocsPage.tsx` и `componentDocs/*` содержат описания и API для сайта.
- `apps/docs/src/components/searchDocs.ts` реализует локальный поиск.
- `tools/catalog` генерирует каталог Button и Input из текущих публичных типов и метаданных всех трёх слоёв. Команды: `pnpm catalog`, `pnpm catalog:test`.
- RAG-индекс и браузерный движок модели ещё отсутствуют; API-таблицы сайта пока не подключены к каталогу.
- Прежние шаги по созданию Vite-приложения, `App.tsx`, `pages.json` и единственной страницы с якорями отменены этим планом.

- [x] Задать явный список входных пакетов и их публичных точек входа. Извлекать экспортируемые символы и свойства через TypeScript; учитывать унаследованные DOM-пропсы, объединения типов и варианты Button-ссылки.
- [x] Отделить извлекаемые факты от ручных метаданных: описание, ограничения и проверенные значения по умолчанию. Метаданные не должны повторять типы пропсов.
- [x] Построить записи Button и Input по реально доступным слоям. Для каждого слоя указать свой экспорт и контракт; не приписывать отсутствующие реализации.
- [x] Проверять примеры через публичные импорты и TypeScript. Не исполнять примеры во время построения каталога.

**Готово:** одна запись Button или Input пригодна для сайта и внешнего агента; генератор не зависит от HTML документации и AI-runtime.

- [ ] Подключить динамическую загрузку движка в Worker после явного действия пользователя; показать размер загрузки и требования до запуска.

**Готово:** помощник отвечает по общим источникам, а ошибки модели не лишают пользователя поиска.

## Отдельный этап второго AI-контура

Skill и MCP читают тот же формат каталога. Их реализация не входит в браузерный RAG и не блокирует сайт. Проверка совместимости потребителей с форматом каталога обязательна при их подключении.

## Рабочие ограничения

Сохранять структуру трёх слоёв библиотеки, CSS Modules, токены и публичные импорты. Не создавать AI-runtime-зависимости в библиотечных пакетах. Существующие изменения пользователя вне задачи не включать в коммиты.
