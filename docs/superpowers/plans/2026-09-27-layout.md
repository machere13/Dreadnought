# Compound Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a reusable `Layout` with `Header`, `Content`, `Footer`, and collapsible `Sidebar` for the landing page and documentation site.

**Architecture:** React adapters supply semantic markup and Sidebar state without importing styles. The ready `@dreadnought/ui/react` facade composes those adapters and maps CSS Module classes to theme tokens. No new `core` abstraction is needed for container markup or boolean toggling.

**Tech Stack:** TypeScript, React 19, CSS Modules, CSS custom properties, Vitest, Testing Library, Storybook.

**Spec:** `docs/superpowers/specs/2026-09-27-layout-design.md`

## Global Constraints

- Public ready API: `Layout.Header`, `Layout.Content`, `Layout.Footer`, `Layout.Sidebar` from `@dreadnought/ui/react`.
- Public unstyled API: `LayoutAdapter`, `LayoutHeaderAdapter`, `LayoutContentAdapter`, `LayoutFooterAdapter`, `LayoutSidebarAdapter` from `@dreadnought/react/unstyled`.
- `Layout.direction` is `vertical` or `horizontal`, default `vertical`; no implicit React-children inspection.
- Sidebar supports `collapsed`, `defaultCollapsed`, `onCollapsedChange`; controlled mode never mutates its own state.
- Sidebar body stays mounted but is `hidden` when collapsed; its trigger remains visible, is keyboard operable, and has `aria-expanded`/`aria-controls`.
- No built-in menu, responsive breakpoint, overlay, sticky mode, or automatic mobile hiding.
- Follow `docs/conventions.md`: PascalCase component names, real `.ts`/`.tsx` import extensions, separate mirrored tests, CSS Modules and component tokens referencing global tokens.
- Each finished task gets a commit; after full verification, merge locally to `main` without touching the pre-existing deletion `packages/core/src/behaviors/.keep` or pushing.

## File Map

- `packages/adapters/react/src/Layout/Layout/{LayoutAdapter,LayoutHeaderAdapter,LayoutContentAdapter,LayoutFooterAdapter,LayoutSidebarAdapter}.tsx`: focused semantic adapters and Sidebar state; `index.ts` is their barrel.
- `packages/adapters/react/src/{unstyled,index}.ts`: public exports; `packages/adapters/react/tests/Layout/Layout/*`: behavior and type tests.
- `packages/ui/src/adapters/react/components/Layout/Layout/{Layout,LayoutHeader,LayoutContent,LayoutFooter,LayoutSidebar}.tsx`: thin ready facades; local `index.ts` and parent `components/index.ts` expose them.
- `packages/ui/src/presentation/Layout/Layout/{Layout.module.css,layoutPresentation,index.ts}` and `presentation/index.ts`: framework-shared appearance and class map.
- `packages/themes/src/default/tokens/components/Layout/Layout/{colors,spacing,sizing,typography}.tokens.css` plus `index.css`; `components/Layout/Layout/{typography,index}.css`; default `index.css`: theme values and text classes.
- Mirrored UI/theme tests, `apps/storybook/stories/Layout.stories.tsx`, `docs/components/layout.md`, `docs/site-components.md`, and `tsconfig.type-tests.json` complete the component.

## Review Focus

1. `collapsed={false}` must override `defaultCollapsed={true}`; test in Task 1.
2. Repeated clicks in controlled mode must request the same next value until parent rerenders; test in Task 1.
3. A collapsed body containing a focusable link must be hidden but mounted, while trigger remains a native non-submitting button; test in Task 1.
4. Nested horizontal Layout must not reorder Header, Sidebar, Content, Footer or add a second `main`; test in Task 1.
5. Importing ready Layout on the same page must not add presentation classes to `LayoutAdapter`; test in Task 2.

### Task 1: Semantic Layout adapters and Sidebar behavior

**Files:** Create the six files under `packages/adapters/react/src/Layout/Layout/` from the File Map; add `packages/adapters/react/tests/Layout/Layout/LayoutAdapter.test.tsx`, `LayoutSidebarAdapter.test.tsx`, `LayoutAdapter.types.tsx`; modify both adapter package entrypoints and `tsconfig.type-tests.json`.

**Interfaces:** Produces `LayoutDirection = 'vertical' | 'horizontal'`, `LayoutAdapterProps = ComponentPropsWithRef<'div'> & { direction?: LayoutDirection }`, native element props for Header/Content/Footer, and `LayoutSidebarAdapterProps = ComponentPropsWithRef<'aside'> & { collapsed?: boolean; defaultCollapsed?: boolean; onCollapsedChange?: (next: boolean) => void; expandLabel?: string; collapseLabel?: string; slotClassNames?: Partial<Record<'body' | 'trigger', string>> }`. Later tasks consume these exports without importing internal files.

- [ ] **Step 1: Write failing adapter tests and types.** Cover nested DOM order/semantics, default vertical and explicit horizontal direction, forwarded refs/native attributes, controlled and uncontrolled Sidebar, hidden-but-mounted child links, generated `aria-controls`, button `type="button"`, keyboard activation, and Review Focus cases 1–4. Example:

```tsx
render(<LayoutSidebarAdapter defaultCollapsed><a href="/docs">Docs</a></LayoutSidebarAdapter>);
const trigger = screen.getByRole('button', { name: 'Expand sidebar' });
expect(trigger).toHaveAttribute('aria-expanded', 'false');
expect(screen.getByRole('link', { name: 'Docs', hidden: true }).parentElement).toHaveAttribute('hidden');
await user.click(trigger);
expect(trigger).toHaveAttribute('aria-expanded', 'true');
```

- [ ] **Step 2: Verify red.** Run `pnpm exec vitest run packages/adapters/react/tests/Layout/Layout` and `pnpm typecheck`. Expected: missing adapter exports.
- [ ] **Step 3: Implement adapters.** Header/Content/Footer forward native props and refs to `header`/`main`/`footer`; root renders `div` with `data-direction` and defaults to `vertical`. Sidebar renders `aside`, a native `button`, and a `div` body with `hidden={isCollapsed}`. Its state logic is:

```tsx
const [internalCollapsed, setInternalCollapsed] = useState(defaultCollapsed ?? false);
const isCollapsed = collapsed !== undefined ? collapsed : internalCollapsed;
const bodyId = useId();
function toggle() {
  const next = !isCollapsed;
  if (collapsed === undefined) setInternalCollapsed(next);
  onCollapsedChange?.(next);
}
```

Use `aria-controls={bodyId}`, `aria-expanded={!isCollapsed}`, a state-dependent accessible name, `type="button"`, `data-collapsed`, and slot classes. Never spread native props after explicitly set state/ARIA fields so callers cannot accidentally break the contract.

### Task 2: Ready Layout, CSS Modules, and theme

**Files:** Create UI and theme files from the File Map; modify `packages/ui/src/{presentation/index.ts,adapters/react/components/index.ts}`, `packages/themes/src/default/index.css`, `packages/themes/tests/default/theme.test.ts`, and `tsconfig.type-tests.json`; add mirrored UI component and theme tests.

**Interfaces:** Consumes Task 1's five public adapters. Produces `Layout` with statically attached `Header`, `Content`, `Footer`, `Sidebar`; each child facade accepts its corresponding adapter props and `className`. Sidebar forwards `slotClassNames.body/trigger` and merges consumer classes with presentation classes.

- [ ] **Step 2: Verify red.** Run `pnpm exec vitest run packages/ui/tests/adapters/react/components/Layout/Layout packages/themes/tests/default/Layout/Layout` and `pnpm typecheck`. Expected: ready `Layout` and theme entries missing.
- [ ] **Step 3: Implement thin facades.** Use the following composition so one public `Layout` export exposes the four parts; each facade only maps adapter props and CSS Module classes. Merge Sidebar slots the same way. CSS Module owns flex direction, surfaces, spacing, and Sidebar width. The adapter's `hidden` attribute owns hiding; do not implement Sidebar state a second time.

```tsx
function LayoutRoot({ className, ...props }: LayoutAdapterProps) {
  return <LayoutAdapter {...props} className={[layoutPresentation.root, className].filter(Boolean).join(' ')} />;
}
export const Layout = Object.assign(LayoutRoot, {
  Header: LayoutHeader, Content: LayoutContent, Footer: LayoutFooter, Sidebar: LayoutSidebar,
});
```

- [ ] **Step 4: Add tokens and import barrels.** Define color roles from existing `--dreadnought-color-surface-*`, text from `--dreadnought-color-text-primary`, spacing from `--dreadnought-spacing-*`, and size tokens through global sizing tokens. Add named global sizes if none exist, then map component tokens to them; no magic numbers in component tokens. Do not put raw colors in component CSS or use `!important`. Import one `Layout/Layout/index.css` from default theme entry and update the exact-import theme test.

```css

  --dreadnought-layout-header-bg: var(--dreadnought-color-surface-default);
  --dreadnought-layout-sidebar-bg: var(--dreadnought-color-surface-subtle);
```

- [ ] **Step 5: Verify green.** Run targeted tests, `pnpm build`, `pnpm typecheck`, and `pnpm test`. Expected: no new failures and raw adapter still has no ready classes.
