# Alert Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить постоянный контекстный `Alert` с основными возможностями Ant Design, не нарушая три слоя Dreadnought.

**Architecture:** Неоформленный React-адаптер отвечает за DOM, роли и закрытие. Готовый UI-фасад подставляет стандартные иконки, CSS Module и вариант оформления; тема задаёт все цвета, отступы и типографику. В `core` ничего не добавляется без самостоятельного правила.

**Tech Stack:** TypeScript 5.7, React 19, CSS Modules, CSS custom properties, Vitest 3, Testing Library, Storybook, pnpm 9.6.

**Spec:** `docs/superpowers/specs/2026-09-27-alert-design.md`

## Global Constraints

- Публичные входы: `AlertAdapter` из `@dreadnought/react/unstyled`, `Alert` из `@dreadnought/ui/react`; внутренние файлы не становятся публичными путями.
- `type`: `info | success | warning | error`, начальное значение `info`; `variant`: `outlined | filled`, начальное значение `outlined`.
- Хотя бы одно из `title` или `description` обязательно на уровне TypeScript; `action` необязателен.
- `showIcon` по умолчанию `false`; `icon` работает только при `showIcon`; готовый фасад выбирает стандартную иконку по типу.
- `closable` по умолчанию `false`; закрытие локально, без таймера и анимации; `banner` и `Alert.ErrorBoundary` не включать.
- `warning`/`error` получают `role="alert"`, `info`/`success` — `role="status"`; переданный пользователем `role` побеждает.
- CSS только в третьем слое: CSS Module, `@layer dreadnought`, токены темы без `!important`; структура семейства `Feedback/Alert` повторяется в `src` и `tests`.
- Не включать пользовательское удаление `packages/core/src/behaviors/.keep` в коммиты.

### Task 2: Закрытие Alert

**Files:** Modify `packages/adapters/react/src/Feedback/Alert/AlertAdapter.tsx`, `packages/adapters/react/tests/Feedback/Alert/{AlertAdapter.test.tsx,AlertAdapter.types.tsx}`.

**Interfaces:** Extends `AlertAdapterProps` with `closable?: boolean | { closeIcon?: ReactNode; onClose?: (event: MouseEvent<HTMLButtonElement>) => void; 'aria-label'?: string }`. `AlertAdapter` returns `null` after its own close button is activated; no timer or controlled visibility prop.

- [ ] **Step 1: Write failing behavior tests** with `userEvent`:

```tsx

render(<form onSubmit={submit}><AlertAdapter title="First" closable={{ onClose, 'aria-label': 'Close first', closeIcon: <svg /> }} /><AlertAdapter title="Second" closable /></form>);

expect(screen.queryByText('First')).toBeNull();
expect(screen.getByText('Second')).toBeInTheDocument();
expect(onClose).toHaveBeenCalledTimes(1);
expect(submit).not.toHaveBeenCalled();
```

Also assert no close button when `closable` is absent; default accessible name is `Close alert`; Enter/Space close the alert; `action` is not activated by closing; a parent rerender does not reopen a closed instance.
- [ ] **Step 2: Run** the targeted test; expect missing close button/failing assertions.
- [ ] **Step 3: Implement** local `useState(false)` and return `null` when closed. Take `label`, `closeIcon`, and `onClose` from the `closable` config object; preserve `slotClassNames.close` and avoid passing `closable` to the DOM:

```tsx
const [closed, setClosed] = useState(false);
if (closed) return null;
const closeButton = closable && <button type="button" data-slot="close" aria-label={label ?? 'Close alert'} className={slotClassNames?.close} onClick={event => { setClosed(true); onClose?.(event); }}>{closeIcon ?? 'Close'}</button>;
```
- [ ] **Step 4: Run** targeted test and `pnpm typecheck`; expect PASS. Commit only Task 2 paths as `feat(react): add Alert dismissal`.
