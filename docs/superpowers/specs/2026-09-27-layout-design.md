# Составной Layout для Dreadnought

Статус: проектное решение, ожидает проверки перед реализацией.

## Задача и границы

Нужен переиспользуемый каркас для лендинга и документации: шапка, основная область, подвал и при необходимости сворачиваемая боковая область. Пользователь согласовал составной API по образцу Ant Design и уточнил: Sidebar сворачивается, но не создаёт пункты меню и не скрывается автоматически на мобильном. Логотип, ссылки, поиск и навигационные группы передаются как содержимое; они не зашиты в Layout.

В Ant Design `Layout` объединяет `Header`, `Content`, `Footer` и `Sider`, а навигация остаётся отдельным `Menu` ([документация Ant Design](https://ant.design/components/layout/)). В Dreadnought называем боковую часть `Sidebar`, как принято в плане проекта; не копируем весь API `Sider` с breakpoints, темами и режимами, пока для них нет собственного сценария.

## Публичный контракт

Готовый React-компонент экспортируется из `@dreadnought/ui/react` как `Layout` с частями `Layout.Header`, `Layout.Content`, `Layout.Footer`, `Layout.Sidebar`. Неоформленный второй слой экспортирует `LayoutAdapter`, `LayoutHeaderAdapter`, `LayoutContentAdapter`, `LayoutFooterAdapter`, `LayoutSidebarAdapter` из `@dreadnought/react/unstyled`. Части также доступны отдельно в публичной точке входа второго слоя; они не зависят от оформления.

```tsx
<Layout>
  <Layout.Header>Логотип и действия</Layout.Header>
  <Layout direction="horizontal">
    <Layout.Sidebar defaultCollapsed={false} aria-label="Разделы документации">
      {/* Навигацию задаёт приложение */}
    </Layout.Sidebar>
    <Layout.Content>Страница</Layout.Content>
  </Layout>
  <Layout.Footer>Ссылки и копирайт</Layout.Footer>
</Layout>
```

`Layout` — контейнер с `direction="vertical" | "horizontal"`, по умолчанию `vertical`. Явное направление вложенного Layout заменяет хрупкое определение Sidebar через обход React-children и предсказуемо при SSR. `Header`, `Content`, `Footer` принимают обычные атрибуты соответствующих HTML-элементов, `children`, `className`, `ref`; `Sidebar` — атрибуты `aside`, `children`, `className`, `ref` и управление сворачиванием. Проект может использовать части в нужном порядке; если Sidebar нужен справа, он ставится после Content.

## Семантика и поведение

Корень — нейтральный `div`, `Header` — `header`, `Content` — `main`, `Footer` — `footer`, `Sidebar` — `aside`. Sidebar не подменяет собой `nav`: приложению следует вложить собственную навигацию. Потребитель следит, чтобы на странице не оказалось нескольких основных областей `main` без причины.

`Sidebar` поддерживает `collapsed` + `onCollapsedChange` для контролируемого режима и `defaultCollapsed` для неконтролируемого. При отсутствии обоих он открыт. Встроенная кнопка переключения имеет доступное имя, `aria-expanded` и `aria-controls`. При сворачивании содержимое остаётся смонтированным, но скрывается через `hidden`, чтобы недоступные сейчас ссылки не попадали в порядок Tab; кнопка остаётся видимой. Сворачивание меняет ширину только Sidebar и не управляет маршрутом или состоянием меню. Автоматического сворачивания по breakpoint, overlay, sticky-поведения и отдельного мобильного drawer в первой версии нет.

Если `collapsed` передан, нажатие вызывает `onCollapsedChange` с новым значением, но компонент сам не меняет контролируемое состояние. Без `collapsed` он обновляет внутреннее состояние и также вызывает callback. Эти правила проверяются тестами. Для произвольного содержимого не обещаем «иконковый» компактный режим: скрыто всё тело Sidebar, видна только кнопка переключения.

## Слои и оформление

В `core` не создаём абстракции для простой инверсии boolean и контейнерной разметки. Слой 2 содержит React-разметку, ref, обработчик кнопки и семантику; не импортирует стили. Слой 3 добавляет CSS Modules и тему поверх адаптеров. Файлы группируются в семействе `Layout` с зеркальной структурой тестов. Общие цвета, отступы, размеры и типографика идут через глобальные токены; токены `Layout`, `Header`, `Content`, `Footer`, `Sidebar` ссылаются на глобальные. Возможна настройка отдельного экземпляра через локальный класс и component tokens, без `!important`; для значимых внутренних частей Sidebar предоставляются slot-классы.

Стандартная тема сохраняет нынешний графитовый фон и контрастные поверхности. Размеры и отступы остаются токенами; содержимое Header/Footer не получает жёсткой структуры логотипа и ссылок. Второй слой остаётся без библиотечных классов даже на странице, где импортирован третий.

## Проверка и результат

Тесты проверяют HTML-семантику, порядок областей, ref и native props, контролируемое и неконтролируемое сворачивание, клавиатурную активацию кнопки, скрытие тела без размонтирования, отсутствие оформления на адаптерах и определённость CSS-токенов. Storybook показывает каркас лендинга, каркас документации и оба состояния Sidebar. Пишется короткая документация с примером каждого слоя. Сборка, typecheck, все тесты и сборка Storybook должны проходить до локального переноса коммитов в `main`.
