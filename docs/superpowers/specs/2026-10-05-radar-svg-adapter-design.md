# C2: SVG Radar-адаптер второго слоя

## Цель и согласованный состав

Показать несколько серий Radar по независимой модели C1, переключать их видимость с клавиатуры и читать исходные значения без hover. Потребитель может использовать адаптер без темы библиотеки и оформить его самостоятельно.

Согласованы SVG, подписи, HTML-легенда, таблица значений, фиксированный или адаптивный размер и настройка частей через slotProps. Готовое оформление относится к отдельному C3.

Выбран собственный native SVG с существующими buildRadarLayout, getSelectionValue и TableAdapter. Альтернатива — host G2 — потребовала бы новый движок и его lifecycle; для текущего Radar он не нужен. Новых зависимостей, chart engine, общего provider и plugin registry нет.

## Размещение и публичный API

Реализация: packages/adapters/react/src/Visualization/RadarChart/, тесты зеркально в tests/Visualization/RadarChart/. Экспорт RadarChartAdapter и RadarChartAdapterProps через компонентный index.ts, unstyled.ts и корень React-пакета. Публичный импорт — @dreadnought/react/unstyled.

Основные пропсы:

- metrics и series — readonly-данные публичных RadarMetric/RadarSeries из core.
- label — обязательная непустая строка, доступное название графика.
- description — необязательное строковое пояснение.
- width и height — оба заданы либо оба отсутствуют. Заданные размеры — конечные положительные числа в CSS-пикселях.
- visibleSeries — необязательный readonly-массив ID для controlled-режима.
- defaultVisibleSeries — начальная видимость в uncontrolled-режиме; по умолчанию видны все начальные серии.
- onVisibleSeriesChange(next: string[]) — запрос нового набора видимых ID.
- labels — необязательное частичное переопределение строк: legend («Серии»), dataTable («Данные»), metric («Показатель»), domain («Диапазон»), direction («Шкала»), increasing («Больше — дальше от центра»), decreasing («Меньше — дальше от центра»). Все пользовательские подписи выводятся как текст.
- Нативные пропсы figure, включая className, style и ref; children не принимаются, поскольку разметкой владеет адаптер.
- slotProps — публичные точки настройки перечисленных ниже частей.

Полный пример:

```tsx
import { RadarChartAdapter } from '@dreadnought/react/unstyled';

<RadarChartAdapter label="Сравнение вариантов"
  metrics={metrics} series={series} width={400} height={320}
  visibleSeries={visible} onVisibleSeriesChange={setVisible} />;
```

Это React-компонент второго слоя, не универсальный renderer для остальных фреймворков. Будущий Angular-адаптер использует ту же чистую модель core независимо.

Неверные типы/неконечные размеры, неполная пара width/height, пустой или нестроковый label, нестроковый description и неверные строки labels вызывают TypeError; неположительные конечные размеры — RangeError. Пользовательские строки labels должны быть непустыми после trim. Значения не исправляются автоматически.

## Данные и SVG

Адаптер вызывает buildRadarLayout с постоянным модельным radius 100. Все серии валидируются, включая скрытые; скрытие не маскирует ошибку данных. Ошибки C1 передаются вызывающему коду без подстановки нулей или fallback-графика.

SVG использует viewBox -140 -140 280 280 и preserveAspectRatio="xMidYMid meet". Это координатная система и запас для подписей, не значения оформления. Изменение viewport не меняет нормализацию, форму или порядок данных. ViewBox не вычисляется удвоением внешних размеров, чтобы не получить переполнение.

Выводятся радиальные оси, четыре уровня сетки на 25/50/75/100% радиуса и polygon для каждой видимой серии. Координаты серий берутся только из C1. Метрики и серии сохраняют порядок входа; React keys — их точные ID. У частей серий есть data-series-id для идентификации, но индекс палитры адаптер не назначает.

Подписи показателей располагаются за концами осей; привязка текста учитывает сторону оси. Длинные подписи не заменяются сокращениями в исходных данных: полное название всегда присутствует в таблице. Автоматическое измерение текста, предотвращение всех пересечений и гарантированное вмещение произвольной подписи не входят в C2.

SVG не содержит цветов, толщины линии, шрифта или подключённого CSS. Браузерные defaults не являются темой. Paint задаёт потребитель через классы/slotProps либо будущий третий слой. Геометрические SVG-атрибуты принадлежат адаптеру и не заменяются оформлением.

## Размеры, SSR и lifecycle

Фиксированный режим сразу выводит SVG с width/height, включая SSR; обращения к document и измерений нет.

Адаптивный режим наблюдает ширину отдельного plot-контейнера через ResizeObserver. Высота viewport = width × 4/5, соотношение 5:4. Измерение высоты не управляет высотой самого наблюдаемого элемента, поэтому нет resize-петли. Таблица и легенда находятся вне измеряемого контейнера.

SSR и первый клиентский render адаптивного режима выводят одинаковый пустой plot-контейнер; легенда, описание и таблица присутствуют сразу. SVG появляется только после положительного конечного измерения ширины. При ширине 0 SVG отсутствует, состояние выбора и доступные данные сохраняются. Возврат ненулевой ширины восстанавливает SVG.

Observer отключается при unmount и смене режима; запоздалые callbacks не обновляют размонтированный компонент. StrictMode не оставляет лишних observer. Если ResizeObserver недоступен, адаптивный plot остаётся пустым, но данные и легенда доступны; для SVG потребитель задаёт фиксированные размеры. Polyfill не устанавливается автоматически.

## Видимость и клавиатура

Легенда — группа нативных button type="button" в порядке series, с aria-pressed по текущей видимости. Tab, Shift+Tab, Enter и Space выполняются браузером; отдельной roving-навигации нет. У кнопок с пустым label доступным текстом становится ID серии.

Переключение использует getSelectionValue с действием toggle. Отмена события через пользовательский onClick предотвращает переключение. Нельзя скрытно изменять controlled visibleSeries: до нового пропса и SVG, и aria-pressed сохраняют прежний набор. Callback получает независимый массив, входные массивы не меняются. Разрешено скрыть все серии; оси, сетка, легенда и таблица остаются.

Visible/defaultVisibleSeries должны быть массивами строк без повторов; неверная структура — TypeError, повтор ID — RangeError. Неизвестные ID не создают серии и игнорируются при отображении. При изменении series действующая видимость пересекается с текущими ID, без callback на сам render и без автоматического выбора новых серий. При нажатии callback получает только текущие ID. Uncontrolled default читается при mount и далее не переинициализирует выбор; controlled значение определяется актуальным пропсом. При изменении набора данных временно отсутствующий ID может снова появиться только если он сохранился во внешнем controlled-наборе либо внутреннем состоянии, а не по порядковому индексу. Это не требует отдельного реестра ранее встречавшихся ID.

## Доступность и таблица

Root — figure с видимым figcaption из label и необязательным описанием; useId связывает текст и figure без конфликтов нескольких экземпляров/SSR.

SVG декоративный: aria-hidden="true", не получает focus и не дублирует длинную таблицу для screen reader. Отдельных tab-stop на оси или точке нет. Значения доступны в семантической HTML-таблице независимо от видимости полигонов.

Таблица использует существующую составную разметку TableAdapter, а не новый табличный компонент. Caption даёт понятное название; строка соответствует показателю, столбцы — всем сериям, дополнительно выводятся domain и направление шкалы. Заголовки имеют корректный scope. Пустые label заменяются ID только для отображения; исходные значения/label не меняются. Полные строковые подписи с единицами, domain и reverse остаются читаемыми в DOM. Числа отображаются как исходный number без локального пересчёта и округления.

Таблица не скрывается через display:none или aria-hidden и не удаляет скрытые серии. Tooltip не заменяет данные. Проверки семантики не объявляются полным тестированием всех screen reader.

## Настройка частей

slotProps предоставляет plotContainer (div), plot (svg), grid (g), axis (line), axisLabel (text), series (polygon), legend (div), legendButton (button), table (нативные пропсы table без children). Повторяемые axis/axisLabel получают показатель, series/legendButton — серию, чтобы выбрать className, стиль или обработчик по ID. Разметку заголовков и ячеек создаёт существующий TableAdapter; отдельные Radar-слоты для каждой ячейки не вводятся.

Root настраивается нативными пропсами figure. Классы и styles доходят до заявленных частей; обработчики пользователя не теряются. Геометрия, data-ui/data-series-id, тип кнопки, aria-pressed и обязательные ARIA-связи остаются согласованными. Slot types исключают атрибуты, которыми владеет адаптер; runtime-порядок пропсов сохраняет этот контракт и для JavaScript.

Не добавляются составные RadarChartAdapter.Root/Plot/Legend, context/provider или slot для каждого служебного узла. Изменение всей разметки остаётся возможным через самостоятельное использование core.

## Каталог и документация

В явный список компонентов каталога добавляется RadarChart, family Visualization, с реальным binding react-adapter слоя 2. Отдельная domain:build-radar-layout C1 сохраняется и связывается через composesWith; первый слой не объявляется фиктивной функцией состояния компонента. Готового react-ui binding в C2 нет.

Пример публичного импорта адаптера проверяется компилятором каталога и доступен через CLI/MCP. На сайте появляется пример второго слоя с объяснением отсутствия стандартного оформления и доступным переключением серий; стандартные стили демо принадлежат приложению документации, не адаптеру. Storybook-история Unstyled не добавляется по конвенциям.

## Границы и критерии готовности

Нет изменений нормализации C1, готового RadarChart третьего слоя, цветовой палитры, tooltip, анимации, G2, Canvas, zoom/brush или новых зависимостей. Нет сравнительного прогона токенов.

Проверяются: соответствие SVG координатам C1; порядок серий/метрик; reverse; пустые серии; скрытие всех серий; controlled/uncontrolled-переключение и отмена события; смена данных; специальные ID; независимость массивов; нативные props/ref/slot handlers; полные названия и таблица; несколько экземпляров без ARIA-конфликтов; fixed SSR; measured hydration/нулевой контейнер/resize/cleanup/StrictMode; отсутствие ResizeObserver. Неверные dimensions/label/visibleSeries имеют явные ошибки; ошибки C1 не поглощаются.

Публичные типы, каталог/MCP, сборка и полный набор тестов должны проходить. В браузере проверяются клавиатурная легенда и изменение ширины контейнера без window resize. После реализации результат коммитится локально в main, без push.
