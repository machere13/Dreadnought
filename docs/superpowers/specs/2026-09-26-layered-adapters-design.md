# Два вида адаптации в трёх слоях Dreadnought

Статус: согласованное целевое устройство; код ещё не перенесён. Спецификация «оформление по DOM-контракту» отменена: она требовала глобальных селекторов и оформляла бы также компоненты второго слоя.

## Границы слоёв

1. **Core** содержит общую логику, действия и контракты. Он не знает о React, Angular и теме.
2. **Адаптер фреймворка** связывает эту логику с React, Angular и т. д.: создаёт разметку, события, refs, слоты и семантику. `ButtonAdapter`, `InputAdapter`, `TextAreaAdapter` не импортируют оформление и остаются без библиотечных стилей даже тогда, когда в том же приложении используются готовые компоненты.
3. **Визуальный слой** адаптирует дизайн-систему к компонентам второго слоя. Он содержит общие токены и CSS Modules, а также тонкую точку входа для каждого поддерживаемого фреймворка. Например, `@dreadnought/ui/react` экспортирует готовый `Button`: он использует React-`ButtonAdapter`, добавляет классы оформления и подключает стандартные стили и тему. Логика, события и семантика не реализуются повторно.

Направление зависимостей: `ui/react → adapters/react → core`. Общие CSS и токены переиспользуются точками входа других веб-фреймворков. Слой 2 не импортирует слой 3. React- и Angular-фасады третьего слоя различаются только способом соединения с соответствующим адаптером, но не копируют дизайн-систему.

```text
core ──→ React ButtonAdapter ──→ ui/react Button ──→ готовая React-кнопка
     └─→ Angular ButtonAdapter ─→ ui/angular Button ─→ готовая Angular-кнопка
                         общие CSS Modules и токены ↗
```

## Публичное использование

```tsx
import { ButtonAdapter } from '@dreadnought/react/unstyled'; // только слой 2
import { Button } from '@dreadnought/ui/react';               // слои 1–3
```

Потребитель готового `Button` не импортирует вручную `ui/style.css` или стандартную тему: это делает точка входа третьего слоя. Для собственной темы предусмотрена настройка токенов проекта; отдельный способ подключать тему без стандартных значений будет определён при реализации, без неявного переопределения пользовательских файлов.

Другому фреймворку нужны и его адаптер второго слоя, и тонкая точка входа третьего слоя. Утверждение «достаточно добавить только Angular-адаптер второго слоя, чтобы получить готовый Angular-Button» неверно. Переиспользуются именно CSS, токены и визуальные правила, а не React-компонент.

## Миграция и критерии

Текущий код пока устроен иначе: `Button`, `Input`, `TextArea` и `styled.ts` лежат в `packages/adapters/react`, а React-пакет зависит от `@dreadnought/ui`. При реализации оформленные фасады переедут в третий слой, направление зависимости развернётся, а второй слой сохранит публичные `*Adapter`. Изолированное использование адаптера и готового компонента на одной странице должно проверяться тестом: CSS готового компонента не оформляет адаптер. Проверяются также типы, сборка и отсутствие React/Angular в общем `core` и CSS.
