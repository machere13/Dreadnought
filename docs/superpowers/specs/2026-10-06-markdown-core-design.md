# Markdown: чистые операции над текстом

## Цель и границы

Первый шаг к редактору, который можно собрать из core в любом веб-фреймворке. Пользователь утвердил направление: жирный, курсив, ссылка и список, без React и DOM. В текущих исходниках готового MarkdownEditor нет; это новый домен, а не рефакторинг существующего редактора.

Рекомендуется небольшая чистая функция, а не AST-парсер или controller редактора. Парсер нужен для анализа документа целиком, controller — для владения состоянием и историей; этих задач сейчас нет. Операции работают с буквальным исходным текстом, не интерпретируют вложенный Markdown и не обещают toggle форматирования.

## Публичный контракт

`applyMarkdownCommand(document, command)` принимает:

- document: `{ text: string, selection: { start: number, end: number } }`;
- command: `{ type: 'bold' }`, `{ type: 'italic' }`, `{ type: 'link', destination: string }` или `{ type: 'list', ordered?: boolean }`.

Результат имеет ту же форму, что document. Индексы — UTF-16 offsets, как selectionStart/selectionEnd у textarea. start/end — безопасные целые числа: `0 <= start <= end <= text.length`. Выделение направлено от start к end; направление обратного выделения адаптер сохраняет отдельно. Вход не изменяется, выход и selection — новые объекты. Неверные типы и неизвестная команда дают TypeError; неверные границы выделения — RangeError, без скрытого clamp.

```ts
import { applyMarkdownCommand } from '@dreadnought/core';

const next = applyMarkdownCommand(
  { text: 'Hello world', selection: { start: 6, end: 11 } },
  { type: 'bold' },
);
// next: { text: 'Hello **world**', selection: { start: 8, end: 13 } }
```

## Правила команд

### Жирный и курсив

Выделенный фрагмент оборачивается в `**` или `*`. Выходное выделение покрывает исходный фрагмент внутри добавленных маркеров. При пустом выделении вставляются только парные маркеры, курсор остаётся между ними. Существующие маркеры не удаляются и не распознаются; повторный вызов добавляет новую обёртку. Пробелы и переводы строк не нормализуются. Это операция вставки синтаксиса, не гарантия корректного форматирования произвольного фрагмента Markdown.

### Ссылка

Фрагмент становится `[фрагмент](<destination>)`; пустое выделение создаёт пустую подпись и оставляет курсор внутри `[]`. Обратные слеши и квадратные скобки исходной подписи экранируются, чтобы они не закрывали подпись. Выходное выделение покрывает всю экранированную подпись без окружающих скобок.

destination — непустая строка без переводов строк, ASCII whitespace/control characters и `<`/`>`; неверное значение даёт TypeError. Обратные слеши экранируются. Относительные адреса и anchors разрешены. Функция не проверяет доступность адреса и НЕ делает URL безопасным: разрешённые схемы, рендеринг ссылок и HTML sanitization относятся к потребителю. Никакого HTML из core.

### Список

Команда добавляет префикс каждой затронутой строке целиком: `- ` по умолчанию, либо `1. `, `2. ` и далее при ordered=true. Нумерация начинается заново для каждой команды. Префикс вставляется перед существующим отступом; существующие префиксы не удаляются. Пустые строки включены.

Для непустого выделения затрагиваются строки, содержащие символы полуинтервала `[start,end)`: если end стоит в начале следующей строки, она не затрагивается. Для пустого выделения затрагивается текущая строка, включая пустую последнюю строку после перевода. LF и CRLF сохраняются без преобразования; граница между CR и LF относится к предыдущей строке, одиночный CR считается обычным символом.

Выходное выделение сохраняет исходные символы: каждый offset сдвигается на суммарную длину префиксов, вставленных до него или в его позицию. Поэтому курсор в начале строки оказывается после префикса. Новые префиксы между началом и концом выделения попадают в его диапазон.

## Размещение

`packages/core/src/domains/markdown/`: типы рядом с applyMarkdownCommand, index.ts для экспорта; domains/index.ts реэкспортирует домен. Тесты отдельно в `packages/core/tests/domains/markdown/`. Контракт публикуется в существующем каталоге как domain с core binding, ограничениями и runnable примером. Никаких новых зависимостей, CSS, публичных React-хуков или пустых реестров.

Документация core-capabilities обновляется после реализации, не объявляет готовый MarkdownEditor. Подключение к UI — отдельный следующий этап: адаптер читает выделение textarea, выполняет команду, обновляет состояние и восстанавливает выделение после commit. Фокус, IME, controlled-состояние, undo/redo и взаимодействие Toolbar не входят в эту функцию.

## Проверки готовности

Тесты сначала фиксируют буквальные ожидаемые текст и offsets: выделение/пустой курсор, края текста, UTF-16, повторное применение, экранирование подписи, неверный destination, многострочное выделение, конец на границе строки, пустая последняя строка и CRLF. Проверяются отсутствие мутации, ошибки невалидного runtime-входа и публичный импорт/type contract. Каталог, сборка, проверка типов и общий набор тестов должны пройти.

Публичная функция не является Markdown-парсером, sanitizer, историей редактирования или готовым компонентом. Пример с выделением после bold — критерий операции, а не обещание полного редактора.
