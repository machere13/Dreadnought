# Accordion: составной компонент Dreadnought

Статус: предложенный письменный контракт; реализация ещё не начата.

## Задача и границы

`Accordion` раскрывает ответы FAQ на лендинге и дополнительные разделы документации. Заголовок принимает текст и другие неинтерактивные элементы, панель — произвольный контент. По умолчанию открыт не более одного пункта, но `multiple` разрешает несколько. Первоначально всё закрыто; повторная активация открытого пункта закрывает его, поэтому состояние «ничего не открыто» всегда допустимо.

Первая версия не включает анимацию высоты, асинхронную загрузку панели, виртуализацию и перенос DOM-содержимого в портал. Анимацию позднее можно добавить только в визуальном слое, не меняя контракт раскрытия.

## Публичный API

```tsx
<Accordion defaultValue="install" onValueChange={setOpenItem}>
  <Accordion.Item value="install">
    <Accordion.Trigger headingLevel={3}>Как установить?</Accordion.Trigger>
    <Accordion.Panel>Инструкция по установке.</Accordion.Panel>
  </Accordion.Item>
  <Accordion.Item value="theme">
    <Accordion.Trigger headingLevel={3}>Как поменять тему?</Accordion.Trigger>
    <Accordion.Panel>Настройте токены темы.</Accordion.Panel>
  </Accordion.Item>
</Accordion>

<Accordion multiple defaultValue={['install', 'theme']}>
  {/* те же Item / Trigger / Panel */}
</Accordion>
```

`Accordion`, `Accordion.Item`, `Accordion.Trigger`, `Accordion.Panel` — публичные составные части. `Item.value` — непустая уникальная строка внутри одного корня; один `Item` содержит ровно один `Trigger` и одну `Panel`. Повторение или отсутствие пары — ошибка использования API, а не повод молча подобрать другой пункт.

В одиночном режиме `value`/`defaultValue` имеют тип `string | null` (`null` — всё закрыто), `onValueChange` получает тот же тип. В множественном режиме `multiple={true}` эти свойства имеют тип `string[]` (`[]` — всё закрыто). При открытии значение добавляется в конец массива; при закрытии удаляется, порядок остальных сохраняется. `defaultValue` задаёт начальное внутреннее состояние; `value` и `onValueChange` образуют управляемый режим. Одновременная передача `value` и `defaultValue` запрещена типами. Без них компонент неуправляемый и начинается закрытым. Колбэк вызывается при запросе изменения, но не при первом рендере; в управляемом режиме видимое состояние меняется только после обновления `value` родителем.

`className` и `ref` каждой части относятся к её собственному DOM-элементу: корень и `Item` — `<div>`, `Trigger` — `<button>`, `Panel` — `<div>`. Идентификаторы связи кнопки с панелью контролирует адаптер; пользователь не передаёт им собственные `id`. `Trigger` принимает `headingLevel` от 1 до 6, по умолчанию 3; уровень выбирает пользователь согласно иерархии страницы. `Trigger.disabled` блокирует взаимодействие с этим пунктом. Иконка-индикатор раскрытия — декоративная часть готового оформления, не часть доступного имени; второй слой не требует её.

## Поведение и доступность

- `Trigger` — нативный `<button type="button">` внутри заголовка `<h1>`–`<h6>` соответствующего уровня. Внутри заголовка нет другого интерактивного элемента; пользовательский текст и декоративный индикатор находятся внутри кнопки.
- Кнопка получает `aria-expanded`, `aria-controls`; панель имеет стабильный `id` и `aria-labelledby`, указывающий на кнопку. Идентификаторы стабильны при SSR и гидратации. `role="region"` для панели не задаётся по умолчанию, чтобы много пунктов не создавали избыток landmark-областей; при необходимости пользователь может явно передать `role="region"` в `Panel`.
- Панель остаётся в DOM и скрывается атрибутом `hidden`: её локальное состояние сохраняется при закрытии, содержимое не участвует в порядке фокуса. CSS готового компонента обязан сохранять действие `hidden` даже при собственном `display`. Если фокус оказался внутри закрытой панели из-за внешнего изменения управляемого значения, адаптер возвращает его на соответствующий `Trigger`.
- Enter/Space активируют нативную кнопку, Tab/Shift+Tab идут в обычном порядке. Специальную навигацию стрелками в первой версии не добавляем: в [WAI-ARIA Accordion Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/) она необязательна. Клик и клавиатура вызывают одну логику переключения. Отключённая кнопка не переключает состояние и не вызывает колбэк.
- Вложенный `Accordion` имеет собственный контекст и не меняет состояние родительского. Пустые, повторяющиеся и неизвестные `value` в управляемом/начальном состоянии считаются ошибкой контракта; значения не исправляются молча.
- `Item` и `Trigger` отражают открытость через `data-state="open" | "closed"`; визуальный слой использует это для индикатора и оформления, не вычисляя состояние повторно.

## Ответственность слоёв

1. `core/components/Navigation/Accordion` хранит типы выбора и чистую функцию переключения значения для одиночного/множественного режима. Здесь нет React, DOM и CSS. В общий `behaviors/` правило не выносится без второго независимого потребителя.
2. `adapters/react/src/Navigation/Accordion` содержит `useAccordion`, контекст, неоформленный `AccordionAdapter` и части `Item`, `Trigger`, `Panel`. Слой отвечает за состояние, DOM, refs, проверку структуры, события и ARIA-связи. Он не импортирует тему или CSS. Хук экспортируется через `@dreadnought/react/logic`, адаптер — через `@dreadnought/react/unstyled`.
3. `ui/src/presentation/Navigation/Accordion` содержит CSS Module и карту классов, `ui/src/adapters/react/components/Navigation/Accordion` — тонкий готовый фасад. Оформление и декоративный индикатор не повторяют поведение. Токены лежат в `themes/default/tokens/components/Navigation/Accordion`, типографика — в соответствующей папке `components/`; CSS остаётся в `@layer dreadnought` без `!important`.

Импорт `AccordionAdapter` не подключает оформление; импорт `Accordion` из `@dreadnought/ui/react` подключает стандартную тему. Каждая значимая часть имеет свой `className` и компонентные токены, без обращения пользователя к случайной вложенности DOM.

## Проверка результата

- Core: переключение одиночного и множественного режимов, закрытие последнего пункта, неизменность исходного массива.
- Adapter: управляемое/неуправляемое состояние, клик, Enter/Space, disabled, уникальность значений, обязательные пары частей, ARIA-связи, `hidden`, сохранение состояния панели, фокус при закрытии извне и независимость вложенного аккордеона.
- UI: стили есть только у готового компонента, `className` каждой части сохраняется, токены темы и декоративный индикатор работают без изменения разметки второго слоя.
- Storybook показывает FAQ, `multiple` и disabled; документация приводит импорты всех трёх слоёв. Публичная сборка, типы и полный набор тестов проходят.
