# Alert: сообщение в контексте страницы

Статус: проект письменного контракта для проверки; реализация ещё не начата.

## Задача и границы

`Alert` показывает замечание в документации, результат операции или ошибку RAG-помощника непосредственно рядом с соответствующим содержимым. Он остаётся в потоке страницы и не исчезает по таймеру. Это не `Toast` и не глобальный `Message`. Первая версия покрывает основные сценарии `Alert` из Ant Design, но не копирует его внутреннюю реализацию. `banner`, анимация закрытия и `Alert.ErrorBoundary` остаются отдельными задачами.

## Публичный API

```tsx
<Alert type="info" title="Настройка темы" description="Измените токены проекта." />
<Alert
  type="error"
  title="Не удалось получить ответ"
  description="Попробуйте отправить вопрос ещё раз."
  action={<Button onClick={retry}>Повторить</Button>}
  closable={{ onClose: handleClose, 'aria-label': 'Закрыть сообщение' }}
/>
<Alert type="success" title="Сохранено" variant="filled" showIcon />
```

- `type?: 'info' | 'success' | 'warning' | 'error'`, по умолчанию `info`.
- `title` и `description` принимают `ReactNode`; типы требуют указать хотя бы одно из свойств, но не проверяют содержимое React-узла. HTML-строки не интерпретируются как разметка.
- `action?: ReactNode` размещается после текста и не создаёт кнопку автоматически.
- `variant?: 'outlined' | 'filled'`, по умолчанию `outlined`. Это только выбор оформления третьего слоя.
- `showIcon?: boolean`, по умолчанию `false`; `icon?: ReactNode` заменяет иконку типа, когда `showIcon` включён. По умолчанию третий слой выбирает иконку по `type` из стабильного набора `IconName`.
- `closable?: boolean | { closeIcon?: ReactNode; onClose?: (event: MouseEvent<HTMLButtonElement>) => void; 'aria-label'?: string }`, по умолчанию `false`. В готовом компоненте кнопка использует именованную иконку закрытия, в неоформленном адаптере — текст. Если `closeIcon` задан, он заменяет содержимое кнопки, но не её доступное имя.
- `className`, `style`, нативные атрибуты `<div>` и `ref` относятся к корню. `slotClassNames?: { icon?; title?; description?; actions?; close? }` даёт публичные точки для локальной настройки вложенных частей; внутренние классы CSS Module не являются API.

## Поведение и доступность

Адаптер рендерит корневой `<div>`, необязательные части `icon`, `title`, `description`, `actions` и нативную `<button type="button">` для закрытия. Кнопка не отправляет внешнюю форму. Клик или клавиатурная активация закрывают экземпляр без таймера и вызывают `closable.onClose` один раз. После закрытия компонент возвращает `null`; родитель может показать его снова новым экземпляром. Закрытие не запускает `action` и не меняет состояние соседних экземпляров.

По умолчанию `warning` и `error` получают `role="alert"`, а `info` и `success` — `role="status"`; пользовательский `role` имеет приоритет. Иконка скрыта от скринридера, смысл сообщения передаётся текстом. Кнопка закрытия имеет имя `Close alert` по умолчанию или пользовательское `closable['aria-label']`; её графика декоративна. `action` остаётся доступным интерактивным содержимым. При отсутствии `title` или `description` соответствующий пустой узел не создаётся.

## Ответственность слоёв и оформление

1. Новый `AlertCore` не создаём: закрытие локального React-компонента и DOM-семантика пока не образуют самостоятельного правила для `core`.
2. `packages/adapters/react/src/Feedback/Alert/` содержит `AlertAdapter`: разметку, локальное состояние закрытия, обработчики, роли и доступные имена. Импорт из `@dreadnought/react/unstyled` не подключает тему или CSS. `AlertAdapter` позволяет передать собственную иконку и текст кнопки, но не знает стандартной палитры.
3. `packages/ui/src/presentation/Feedback/Alert/` содержит CSS Module и карту классов; `packages/ui/src/adapters/react/components/Feedback/Alert/` — готовый React-фасад с выбором иконки и классов. `themes/default/tokens/components/Feedback/Alert/` задаёт компонентные токены, а типографика лежит в `themes/default/components/Feedback/Alert/`. Публичный вход готового компонента — `@dreadnought/ui/react`.

Стандартная тема остаётся тёмной: у всех типов читаемый текст, единая геометрия, фон и обводка зависят от `type` и `variant`. Цвета `success`, `warning` и `error` используют существующие глобальные роли; для `info` добавляется общая роль `color-status-info`. Компонентные токены ссылаются на глобальные, кроме действительно уникальных значений. Стили только в CSS Module и `@layer dreadnought`, без `!important`; отдельный экземпляр настраивается через токены в пользовательском `className` или `slotClassNames`.

## Проверка результата

- Адаптер: текст и действие отображаются в нужном порядке; отсутствующие части не создаются; роли соответствуют типу и могут быть переопределены; `ref`, нативные атрибуты и классы слотов передаются верно.
- Закрытие: кнопка существует только при `closable`, имеет доступное имя, не отправляет форму; клик и клавиатура скрывают только свой Alert и вызывают колбэк один раз.
- Готовый компонент: четыре типа, два варианта, отсутствие/наличие и замена иконки; адаптер остаётся неоформленным. Токены темы определены и не требуют `!important`.
- Storybook показывает короткое сообщение, описание, четыре типа, оба варианта, действие и закрытие. Документация приводит публичные импорты. Типы, сборка и все тесты workspace проходят.
