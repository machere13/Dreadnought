# C1: независимая модель Radar в core

## Цель и выбранный подход

Сравнить несколько вариантов по показателям с разными единицами: например, качество, покрытие и задержка. Потребитель получает готовые координаты и может нарисовать график в любом фреймворке или без него.

Выбрана чистая функция на TypeScript и стандартном Math. Обёртка над AntV потребовала бы движок для простого расчёта; универсальная система графиков добавила бы пока неиспользуемые контракты. Ни то, ни другое в C1 не добавляется.

Это первый реализуемый домен графиков, а не готовый компонент. React-адаптер и оформление относятся к следующим отдельным этапам C2/C3.

## Публичный вход

`buildRadarLayout({ metrics, series, radius })` импортируется из `@dreadnought/core`.

- `metrics`: readonly-массив минимум из трёх показателей `{ id, label, domain: [min, max], reverse? }`.
- `series`: readonly-массив серий `{ id, label, values: Record<string, number> }`. Пустой массив допустим: возвращаются оси без серий.
- `radius`: обязательное конечное положительное число.

ID — строки, непустые после trim. Сравнение ID точное, без изменения регистра и обрезания пробелов. ID показателей уникальны среди показателей, ID серий — среди серий; между этими двумя наборами совпадение допустимо. label — строка, включая пустую; локализация остаётся у потребителя.

Domain содержит ровно два конечных числа, min < max. reverse — необязательный boolean, по умолчанию false: меньшее исходное значение соответствует большему расстоянию от центра.

Для каждого показателя series.values должен иметь собственное числовое конечное значение с соответствующим ID. Унаследованное свойство не заменяет отсутствующее значение. Границы domain включены. Лишние ключи values игнорируются и не создают дополнительные оси.

## Результат и координаты

Возвращается `{ axes, seriesPoints }`:

- Ось: `{ id, label, domain, reverse, angle, x, y }`. x/y — конец оси на внешнем радиусе.
- Серия: `{ id, label, points }`.
- Точка: `{ metricId, value, normalizedValue, x, y }`. value — исходное значение, normalizedValue — значение после нормализации и reverse, от 0 до 1.

Оси и точки идут в порядке metrics; серии — в порядке series. Центр находится в (0, 0), x направлен вправо, y вниз. Первая ось направлена вверх; следующие идут по часовой стрелке. Угол задаётся в радианах:

`angle[i] = -PI / 2 + 2 * PI * i / metrics.length`.

Обычная нормализация: `t = (value - min) / (max - min)`; при reverse используется `1 - t`. Для конечных крайних number вычисление должно оставаться корректным даже при переполнении промежуточной разности max - min. Это вычисления с точностью JavaScript number, не произвольная точность.

Конец оси: `(radius * cos(angle), radius * sin(angle))`. Точка серии: `(radius * normalizedValue * cos(angle), radius * normalizedValue * sin(angle))`.

Функция детерминированна, не изменяет вход. Выходные массивы и объекты, включая domain, не имеют изменяемых ссылок на входные структуры. Значения около нуля из-за тригонометрической погрешности проверяются с допуском, не округляются для отображения внутри core.

## Ошибки

Неверная структура, неверные типы, пустой ID, отсутствующее значение, NaN и Infinity вызывают TypeError. Недостаточное число показателей, повторяющийся ID, неположительный radius, min >= max или значение вне domain вызывают RangeError.

Нет подстановки нулей, автоматического domain, скрытого clipping или пропуска невалидной серии. Потребитель решает, как показать ошибку или подготовить свои данные.

## Размещение и границы

Реализация находится в `packages/core/src/domains/charts/`; публичный экспорт проходит через index.ts домена, domains и core. Добавляются только файлы, необходимые этой модели, без пустых реестров и будущих графиков.

Публичные типы описывают показатель, серию, вход и результат. Контракт публикуется в существующем машиночитаемом каталоге как domain, с примером импорта только core; возможности core обновляются в документации. Сейчас каталог и MCP допускают только component/action/behavior: C1 добавляет kind:domain и источник метаданных домена, сохраняя прежние категории и запросы. Выдавать предметную геометрию за behavior не нужно.

Core не получает React, DOM, размеры контейнера, цвета, токены, SVG path, события, состояние видимости, легенду, tooltip, анимацию, рейтинги или сравнение площадей многоугольников. Новых зависимостей и изменений Table нет.

## Критерии готовности C1

1. Аналитические тесты координат для трёх и четырёх осей; для четырёх осей радиуса 100 ожидаются верх, право, низ и лево.
2. Проверки середины и границ domain, reverse, отрицательных диапазонов и крайних конечных number без переполнения нормализации.
3. Проверки порядка осей/серий, пустых series, отсутствия мутации и изменяемых ссылок на вход.
4. Явные ошибки всех перечисленных категорий, включая missing, inherited values, повторяющиеся ID и неверный reverse.
5. Пример использует публичный импорт core, не renderer; типы, каталог и сборка проверены, полный набор тестов проходит.

После C1 отдельно реализуется SVG Radar-адаптер. Наличие математической модели не объявляется готовностью визуального компонента.
