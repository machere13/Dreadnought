# Disclosure: общие правила раскрытия

Статус: утверждён пользователем 2026-10-05. Реализация не начата; план `../plans/2026-10-05-disclosure.md` подготовлен для проверки и выбора способа исполнения.

## Цель

Потребитель может собрать свою раскрывающуюся секцию на первом слое без зависимости от React или Accordion. Проверяем повторное использование правил на существующем Accordion и живом примере собственной секции. Внешний API и оформление Accordion не меняются.

Согласованный объём: открыто/закрыто, блокировка переключения, связь кнопки с содержимым. Escape, клик снаружи, позиционирование popup и новые готовые компоненты не входят в этап.

## Выбранный подход

Добавляем две чистые функции в `core/behaviors`, поскольку это вычисление состояния и перехода, а не новый движок полного взаимодействия. Не создаём пустую папку `patterns` или отдельный компонент Disclosure ради названия направления в roadmap.

Альтернативы: общий React-контроллер со своим состоянием, refs и событиями увеличит API без второго реального потребителя; нативный `details/summary` подходит некоторым собственным секциям, но не заменяет существующую управляемую структуру Accordion. Для такого нативного случая потребитель может использовать платформу напрямую, без наших функций.

Новых зависимостей нет. Используем Ponytail: состояние, события и DOM остаются у существующего адаптера либо потребителя.

## Публичный контракт core

Импорт обеих функций и типов — из `@dreadnought/core` через существующие barrels.

```ts
interface DisclosureStateOptions {
  open?: boolean;
  disabled?: boolean;
  triggerId: string;
  panelId: string;
}

interface DisclosureState {
  open: boolean;
  disabled: boolean;
  triggerProps: {
    id: string;
    type: 'button';
    disabled: boolean;
    'aria-expanded': boolean;
    'aria-controls': string;
  };
  panelProps: {
    id: string;
    hidden: boolean;
    'aria-labelledby': string;
  };
}

type DisclosureAction = 'open' | 'close' | 'toggle';
interface DisclosureOptions { disabled?: boolean }

// getDisclosureState(options: DisclosureStateOptions): DisclosureState
// getDisclosureOpen(currentOpen: boolean, action: DisclosureAction,
//   options?: DisclosureOptions): boolean
```

`getDisclosureState` по умолчанию использует `open=false`, `disabled=false`. `hidden` равен `!open`. `disabled` не закрывает уже открытую секцию и не переписывает её входное состояние.

`getDisclosureOpen` возвращает запрошенное следующее значение: true для open, false для close, инверсию для toggle. При disabled возвращает currentOpen для любого действия. Повторное open/close идемпотентно. Функция ничего не сохраняет и не вызывает callback. Внешний владелец может независимо изменить контролируемый open; disabled запрещает запросы через функцию, а не изменения родительского состояния.

ID задаёт вызывающий код. Оба обязательны, непустые, различны и не содержат ASCII-пробельных символов; неверный вход вызывает Error. Глобальную уникальность обеспечивает вызывающий код. Core не генерирует ID и не проверяет существование DOM-узлов. Функции не меняют вход и не импортируют DOM, React, CSS или browser API.

## Доступность и ответственность адаптера

Основа — [W3C APG Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/), проверено 2026-10-05: кнопка переключает содержимое по Enter/Space, aria-expanded отражает видимость; aria-controls в APG опционален. Наш контракт требует явную связь ID, чтобы кнопка и панель не расходились при собственной сборке.

Используем настоящий `button type="button"`; Enter/Space работают нативно, дополнительный keydown не дублирует click. У кнопки должно быть доступное название. PanelProps не навязывает role=region, диалоговую семантику, ловушку фокуса или анимацию.

Потребитель хранит open, применяет возвращённые props к фактическим узлам, вызывает переход на действие и учитывает отменённый пользовательский event. Разрешено controlled либо uncontrolled состояние, но core не владеет ни одним.

Если панель закрывается с фокусом внутри, адаптер возвращает фокус на trigger, не забирая его с другого элемента страницы. В Accordion сохраняем существующий алгоритм восстановления. В собственном React-примере показываем минимальную реализацию этого правила с refs; не выдаём одни ARIA-атрибуты за полный компонент.

## Интеграция с Accordion

Общая функция состояния заменяет ручное вычисление согласованных атрибутов trigger/panel. Генерация стабильных ID остаётся в AccordionItemAdapter, регистрация частей и защита вложенных контекстов сохраняются.

Одиночный/множественный выбор Accordion остаётся на существующем getSelectionValue/toggleAccordionValue. Не заменяем модель коллекции несколькими независимыми boolean-состояниями. getDisclosureOpen используется в собственной секции; не добавляем бессмысленный промежуточный переход в выбор Accordion только ради вызова новой функции.

Не меняем публичные props, headingLevel, сохранение mounted-содержимого, refs, consumer handlers или стандартную тему Accordion.

## Каталог и документация

Публикуем два standalone behavior entry: `behavior:get-disclosure-state` и `behavior:get-disclosure-open`. Core bindings framework=null, exportName соответствует функции; React-код не выдаётся за framework-independent пример. Каталог связывает функцию состояния с Accordion и функцию перехода с примером собственного раскрытия.

Примеры импортируют только публичные entrypoints и проверяются TypeScript. В `/custom-components/` добавляем живую собственную секцию с нативной кнопкой и полем внутри панели, пояснение о состоянии/событиях/фокусе и пример кода. Новая страница готового компонента и отдельная Storybook-история не нужны.

Обновляем core-capabilities: Toolbar уже реализован, Disclosure — реализованные общие правила с явно обозначенной ответственностью адаптера. Число component entries остаётся 19; standalone capabilities увеличивается с 8 до 10, суммарное число entries — 29. Generated outputs создаются штатными командами; в Git попадают только уже отслеживаемые файлы.

## Проверки и границы завершения

- Чистые функции: дефолты, открыто/закрыто, все три действия, disabled при обоих состояниях, идемпотентность, неизменность входа, неверные и разные ID.
- Accordion: существующие проверки single/multiple, native disabled, отмены click, refs, ARIA-связей, nested isolation и восстановления фокуса остаются зелёными; публичные типы не меняются.
- Собственная секция: мышь, Enter/Space без двойного переключения, открытие и скрытие, disabled, type=button внутри формы без submit, закрытие с фокусом внутри и отсутствие перехвата внешнего фокуса.
- Каталог: оба публичных core binding, корректные signatures/examples, новые standalone counts; документы и примеры соответствуют реальному API.
- Core/React/UI builds, public type checks, docs build и полный Vitest последовательно, exit 0. Браузерная проверка описывается честно: если недоступна, результат не объявляется визуально подтверждённым.

Работа локально в main, завершённые этапы коммитятся без push. Два существующих удаления комментариев в getNextEnabledValue/getSelectionValue принадлежат пользователю и исключаются из коммитов.
