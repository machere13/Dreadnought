# Storybook для просмотра компонентов Dreadnought

## Задача

Дать разработчику отдельную локальную площадку для просмотра готовых компонентов, их состояний и вариантов оформления. Storybook — инструмент разработки и демонстрации, не часть публичных пакетов и не замена документации или существующим автоматическим тестам.

## Размещение и зависимости

Создать приватный workspace-пакет `examples/storybook` с конфигурацией `.storybook/` и историями компонентов. Он использует React, Vite и Storybook для React/Vite, импортируя компоненты только через публичный `@dreadnought/ui/react`. При демонстрации второго слоя истории используют `@dreadnought/react/unstyled`; внутренние пути `src/` не импортируются. Зависимости Storybook остаются только в этом примере, а не в `packages/core`, `packages/adapters/react`, `packages/ui` или `packages/themes`.

На машине доступен Node.js 22 и pnpm 9; они удовлетворяют [текущим требованиям Storybook](https://storybook.js.org/docs/get-started/install/). При установке фиксируется совместимая версия пакетов Storybook в lockfile. Не запускать генератор с примерными компонентами, которые не принадлежат Dreadnought, либо удалить их из итоговой конфигурации.

## Истории и запуск

Сначала добавить истории для существующих `Button`, `Input` и `TextArea`: основные состояния, варианты и характерные взаимодействия. После реализации Badge добавить самостоятельную метку, метку с иконкой, вариант с обводкой и метку поверх элемента. Истории пишутся в TypeScript/CSF с типизированными `Meta` и `StoryObj`; [Controls](https://storybook.js.org/docs/writing-stories/args) позволяют менять доступные props. Не дублировать тестовые фикстуры или исходники компонентов.

Корневые команды запускают локальный Storybook и собирают его статическую версию. Стандартная тема подключается обычным импортом `@dreadnought/ui/react`; отдельного импорта CSS в каждой истории нет. Истории пользовательской темы добавляются только вместе с реальной второй темой. Предпросмотр должен работать после чистой установки workspace-зависимостей и сборки библиотечных пакетов.

## Границы и проверка

Не добавляем пока документационный аддон, визуальные снапшоты, тестовый раннер Storybook и публикацию статического сайта: задача — смотреть компоненты. Существующие Vitest-тесты остаются источником автоматической проверки поведения. Проверить локальный запуск, статическую сборку Storybook, типы историй и то, что публичные пакеты не получили зависимость от Storybook. Артефакты статической сборки игнорируются Git.
