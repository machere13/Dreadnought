# Локальный MCP-доступ к каталогу Dreadnought

Статус: согласовано; реализация ещё не начата. Основа — существующий каталог схемы 1 и операции `tools/catalog/src/query/`.

## Цель

AI-клиент, работающий с внешним проектом, должен запрашивать доступные компоненты Dreadnought, их публичные привязки, контракты, примеры и токены через локальный MCP. Результат должен совпадать по смыслу с уже реализованным JSON CLI. Сервер не создаёт компоненты, не меняет пользовательский проект и не заменяет агента, выбирающего слой.

Успех: клиент подключается к запущенному локальному процессу, видит четыре инструмента, проверяет версии установленной библиотеки и получает данные только из совместимого каталога. При несовместимости он получает объяснимую ошибку, а не API другого выпуска.

## Выбранный подход

Небольшая MCP-оболочка поверх `executeQuery`, без второй реализации поиска и проверки версий. Использовать официальный TypeScript SDK v2 (`@modelcontextprotocol/server`) и локальный stdio-транспорт `serveStdio`; схема аргументов инструментов задаётся Zod. SDK отвечает за протокол и проверку входа, существующие функции каталога — за данные и доменные ошибки. [SDK v2](https://ts.sdk.modelcontextprotocol.io/v2/), [stdio](https://ts.sdk.modelcontextprotocol.io/v2/api/%40modelcontextprotocol/server/server/serveStdio.html).

Рассмотренные альтернативы: ручной JSON-RPC не добавляет зависимостей, но заставляет поддерживать меняющийся протокол; запуск CLI как подпроцесса на каждый MCP-вызов повторно поднимает Node и смешивает два слоя обработки ошибок. Оба варианта хуже для этого локального сервера.

## Границы и конфигурация

- Сервер запускается AI-клиентом как локальный процесс Node.js. Только stdio; ни HTTP-порта, ни входящих сетевых соединений.
- Абсолютные пути `--catalog` и `--project` обязательны при запуске сервера. Они фиксируются на весь срок подключения. Аргументы MCP-инструментов **не** принимают произвольные пути. Это не даёт модели переключить источник или читать package.json другого проекта через инструмент.
- Сервер не запускает генератор каталога, не устанавливает пакеты и не подбирает другую версию из сети. Для каталога из изменённых исходников разработчик заранее выполняет `pnpm catalog`.
- Подключение к исходному монорепозиторию без установленных в нём пакетов Dreadnought может дать `incompatible`; это ожидаемый отказ проверки внешнего проекта, а не повод отключить контроль версий.
- Зависимости MCP остаются только у инструментария, не у `@dreadnought/core`, адаптеров, UI, тем или сайта документации. Командный JSON-интерфейс остаётся доступным без MCP.

## Инструменты

Имена стабильны и явно отделены от других серверов: `dreadnought_check`, `dreadnought_list`, `dreadnought_search`, `dreadnought_get`. Их описания сообщают, что данные локальны, версии проверяются, а `framework: core` означает первый слой, не React-хук.

| MCP-инструмент | Аргументы клиента | Операция каталога |
| --- | --- | --- |
| `dreadnought_check` | нет | `check` для зафиксированного проекта |
| `dreadnought_list` | `family?`, `layer?`, `framework?`, `limit?`, `offset?` | `list` с теми же фильтрами |
| `dreadnought_search` | `query`, затем те же необязательные фильтры | `search` |
| `dreadnought_get` | `component`, `binding?`, `section?`, `property?`, `includeInherited?`, `example?` | `get` |

Схемы повторяют действующие границы: `limit` 1–50, `offset` от 0, `layer` 1–3, разделы `overview`, `api`, `examples`, `tokens`; неизвестные поля отклоняются. `get` не выбирает binding автоматически. Для API и примеров binding обязателен, токены принадлежат компоненту. Результат сохраняет индексы перегрузок и ветвей, отсутствие свойства в отдельной ветви и `propertyPath` составного экспорта вроде `Layout.Sidebar`.

## Ответы и ошибки

- Успешный MCP-вызов возвращает `structuredContent` с неизменённым конвертом `executeQuery`: `responseVersion`, `operation`, `packageVersions`, `compatibility`, `result`. Для клиентов, читающих только текст, тот же JSON помещается в один текстовый блок `content`.
- `check` при несовпадении версий возвращает полный отчёт совместимости как успешный ответ инструмента: это результат проверки, а не сбой транспорта. `list`, `search` и `get` при несовместимости возвращают `isError: true` и структурированный код `VERSION_MISMATCH` или `NO_PACKAGES`. Отсутствующий пакет выбранного binding сохраняет `MISSING_BINDING_PACKAGE`.
- Невалидные аргументы отклоняет схема SDK; доменные ошибки `CatalogQueryError` преобразуются в результат инструмента с `isError: true` и конвертом `{responseVersion, operation, error: {code, message, details}}`. Неожиданная ошибка становится `INTERNAL_ERROR` без stack trace в протокольном ответе.
- stdout зарезервирован исключительно для MCP. Диагностика, если нужна, идёт в stderr и не включает содержимое проекта или каталога целиком. Метаданные каталога считаются данными, а не командами для исполнения.
- Каждая операция читает актуальный локальный JSON и заново проверяет установленные версии; сервер не держит устаревающий снимок между вызовами. Пустой поиск — успешный результат `total: 0`.

## Структура изменений

Новая точка входа сервера и регистрация инструментов живут рядом с `tools/catalog/src/query/`, но не внутри пакетов библиотеки. Тонкая функция сопоставляет MCP-аргументы с запросом `executeQuery` и формирует ответ SDK. Общая логика чтения, фильтрации и проверки версий остаётся в текущих модулях. В корневом `package.json` появляется команда запуска MCP; `tools/catalog/README.md` описывает настройку клиента с двумя абсолютными путями. Переносимый `tools/skills/dreadnought/SKILL.md` учит использовать подключённый MCP либо существующий CLI как запасной путь, без копии перечня компонентов и пропсов.

## Проверка

1. Автоматический тест через настоящий клиент SDK запускает сервер как подпроцесс, выполняет подключение, `tools/list` и каждый из четырёх вызовов. Проверяет, что stdout не загрязняется логами.
2. Тесты с временным внешним проектом проверяют совпадающие версии, частичный набор, полное отсутствие и несовпадение; MCP и CLI дают одинаковый доменный результат при тех же входах.
3. Контрольные запросы: Button-ссылка с `HTMLAnchorElement` ref, `Layout.Sidebar` с `propertyPath`, поиск Angular без выдуманной React-реализации, пустой поиск, неверный фильтр и повреждённый каталог.
4. Существующие тесты каталога, генерация 14 компонентов, проверка типов и сборка сайта продолжают проходить. Депенденции пакетов библиотеки и поведение браузерного RAG не меняются.

## Не входит

Публикация MCP-сервера или пакетов в npm, автоматическая регистрация в Codex/Claude/другом клиенте, HTTP-транспорт, авторизация сетевого сервиса, write-инструменты, выполнение кода из примеров, генерация каталога по MCP и управление пользовательскими зависимостями.
