# Оформление по DOM-контракту для разных веб-фреймворков

Статус: на согласовании. Решение заменяет перенос готовых React-компонентов в пакет адаптера из коммита `9ac9323`.

## Цель и границы

Чтобы подключить Angular, достаточно реализовать адаптер второго слоя: CSS третьего слоя и стандартная тема не копируются и не переписываются. Первый слой по-прежнему не зависит от фреймворка, второй отвечает за DOM, события и refs, третий — только за внешний вид. В этой работе меняются Button, Input и TextArea; Angular-адаптер не создаётся.

## Решение

Адаптер выдаёт документированный DOM-контракт: корневой атрибут `data-dreadnought-ui="button" | "input" | "text-area"`, слоты `data-slot` и состояния `data-loading`, `data-invalid`, `data-disabled`, `data-auto-size` и т. д. Вариант кнопки передаётся как `variant="primary" | "secondary"` и отражается в `data-variant`. Адаптер не импортирует `@dreadnought/ui`, CSS-классы или значения токенов.

В `@dreadnought/ui` остаются `*.module.css`, но вместо локальных классов для оформления используются `:global(...)`-селекторы, ограниченные **только** корневым пространством имён `[data-dreadnought-ui="…"]` и документированными слотами/состояниями внутри него. Это осознанное исключение из прежнего запрета глобальных селекторов компонентов. Не допускаются общие селекторы `button`, `input`, `[data-slot]` без корневого ограничения и глобальный reset. Визуальные значения остаются CSS-переменными темы.

Подключение выглядит так:

```tsx
import { Button } from '@dreadnought/react';
import '@dreadnought/ui/style.css';
import '@dreadnought/themes/default.css';

<Button variant="secondary">Действие</Button>
```

`Button`, `Input` и `TextArea` — публичные имена адаптерных компонентов; отдельной React-обёртки `styled` больше нет. `ButtonAdapter`, `InputAdapter`, `TextAreaAdapter` остаются доступными как явные имена второго слоя. Готовый вид получается из адаптера и отдельно подключённого CSS, а не из ещё одного React-компонента. Другой веб-адаптер реализует тот же DOM-контракт и подключает тот же `@dreadnought/ui/style.css`.

`@dreadnought/react/logic` и `@dreadnought/react/unstyled` не импортируют стили. Но если приложение уже подключило `ui/style.css` глобально, подходящая адаптерная разметка тоже оформится; слово `unstyled` здесь означает отсутствие собственного CSS-импорта, а не иммунитет к CSS страницы. Для полностью своего оформления проект не подключает стандартный CSS на соответствующей странице либо строит собственную разметку из React-хуков и `core`. Это ограничение подхода, которое нельзя скрывать документацией.

## Пакеты и миграция

- `@dreadnought/core`: без изменений.
- `@dreadnought/react`: не зависит от `@dreadnought/ui`; удаляются `Button.tsx`, `Input.tsx`, `TextArea.tsx` как styled-обёртки и подмаршрут `/styled`. Публичные краткие имена реэкспортируют соответствующие адаптеры. ButtonAdapter получает отражение `variant` в DOM без CSS-зависимости.
- `@dreadnought/ui`: публикует CSS и не экспортирует карты локальных классов `*Presentation`, поскольку адаптеру они больше не нужны. CSS Modules служат организацией исходников; в опубликованном CSS действуют только ограниченные атрибутные селекторы.
- `@dreadnought/themes`: сохраняет отдельный импорт стандартных значений токенов.

Переходный пример и документация заменяют `@dreadnought/react/styled` на `@dreadnought/react` и явно подключают `@dreadnought/ui/style.css`. Это изменение публичного API до стабильного релиза; автоматической совместимости старого `/styled` не обещаем.

## Проверка

Тесты сначала должны зафиксировать отсутствие зависимости React → UI, отсутствие React/JSX в UI, одинаковый DOM-контракт у кнопки, ссылки, Input и TextArea, вариант и состояния. Проверка собранного CSS должна подтвердить наличие ограниченных селекторов и отсутствие случайного глобального оформления. Затем проверяются полный набор тестов, типы, сборка React-примера с явным CSS-импортом и отсутствие CSS-импорта из `logic`/`unstyled`.
