# Badge: дизайн компонента

## Цель и границы

Добавить в Dreadnought переиспользуемую метку для лендинга, документации и других веб-проектов. Один компонент поддерживает самостоятельную метку с текстом и/или иконкой и метку поверх произвольного элемента. Значения и внешний вид меняются через тему, без копирования компонента между проектами. Badge сам не является кнопкой, ссылкой или живым уведомлением.

Не включаем в первую версию автоматическое форматирование чисел, ограничение счётчика, скрытие нуля, анимацию изменения значения и набор статусных цветов. Эти возможности добавляются при появлении реального сценария и собственного контракта.

## Публичный API

`children` всегда означает содержимое метки, независимо от режима. `target` — необязательный React-элемент, поверх которого она размещается. `icon` добавляет графический элемент к содержимому; порядок иконки и текста задаётся `iconPosition: 'start' | 'end'` (по умолчанию `start`). `appearance: 'solid' | 'outline'` (по умолчанию `solid`) выбирает вариант оформления. `className`, `ref: Ref<HTMLSpanElement>` и стандартные атрибуты корневого `<span>` передаются без потерь. Число `0` отображается как обычное содержимое, а не скрывается автоматически.

```tsx
<Badge icon={<StarIcon />}>Beta</Badge>
<Badge appearance="outline">New</Badge>
<Badge target={<Button aria-label="Уведомления, 3 новых" />}>3</Badge>
```

В режиме с `target` компонент создаёт неинтерактивную обёртку и отдельную метку; целевой элемент не клонируется, его обработчики, ref и фокус не изменяются. `target` может быть любым React-элементом. В самостоятельном режиме корень — сама метка.

## Распределение по слоям

- **Первый слой (`core`):** новой реализации пока нет. Для расположения и отображения статического содержимого не требуется общая логика. Если позже появятся правила отображения счётчика, они станут чистой функцией и контрактом первого слоя, а не будут дублироваться в адаптерах.
- **Второй слой (`@dreadnought/react/unstyled`):** `BadgeAdapter` задаёт DOM-структуру, части `target`/`badge`/`icon`/`label`, порядок элементов и передачу атрибутов. Не импортирует CSS и не знает цветов темы.
- **Третий слой (`@dreadnought/ui/react`):** `Badge` применяет общую карту классов и CSS Module к адаптеру. Оформление реализовано через стандартную тему и токены; общий CSS не привязан к React.

Файлы компонента располагаются в семействе `DataDisplay/Badge` в адаптере, UI, теме и зеркальных тестах. Публичные импорты идут через существующие точки входа пакетов; внутренние пути не становятся API. Отсутствие папки Badge в `core` намеренно, а не нарушение трёхслойной архитектуры.

## Оформление и доступность

Внешний вид `solid` и `outline`, отступы, скругление, типографика, промежуток между иконкой и текстом и положение метки поверх `target` определяются CSS Module и компонентными токенами стандартной темы. Компонентные токены переиспользуют подходящие глобальные токены. Стили находятся в `@layer dreadnought`; локальная настройка доступна через `className` и токены без `!important`. Не создаём отдельный `IconBadge`.

Самостоятельная текстовая метка читается как обычный текст. Обёртка иконки получает `aria-hidden="true"`: важный смысл иконки должен быть передан текстом метки или доступной подписью. В режиме с `target` визуальная метка также скрыта от дерева доступности, чтобы не звучать отдельным числом без контекста. Если число или статус важны, вызывающий код включает их в доступное имя цели либо предоставляет рядом эквивалентный текст. Badge не включает `aria-live` автоматически и не делает обёртку фокусируемой. Это соответствует рекомендации [MUI Badge по доступному имени целевого элемента](https://mui.com/material-ui/react-badge/).

## Проверка

- Самостоятельная метка отображает текст, иконку, их порядок и оба варианта оформления.
- Метка поверх `target` показывает содержимое, включая `0`, без изменения DOM-свойств и взаимодействия цели.
- `className`, стандартные атрибуты и `ref` попадают на оговорённый корневой элемент; интерактивная цель остаётся фокусируемой.
- Импорт `BadgeAdapter` не подключает стили и тему; импорт готового `Badge` подключает их через существующую точку входа.
- Компонентные токены ссылаются на определённые глобальные значения, сборка и тесты всех пакетов проходят, пример использует публичный импорт.
