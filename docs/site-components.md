# Компоненты библиотеки для лендинга и документации

Здесь перечислены **компоненты Dreadnought**, на которых можно построить промо-лендинг и сайт документации с RAG-помощником. Это план развития библиотеки, а не перечень секций страниц. Готовыми сейчас являются `Button`, `Input`, `TextArea` и `Badge`; остальные пункты — кандидаты, которые реализуются по мере работы над сайтами. Один компонент используется на обоих сайтах без копирования реализации.

## Каркас сайтов

- `Header` — верхняя область лендинга и документации.
- `Footer` — нижняя область сайтов.
- `Sidebar` — боковая навигация документации, включая свёрнутое состояние при необходимости.

Это кандидаты для библиотеки: они задают переиспользуемую структуру и оформление, но не конкретные логотип, ссылки и тексты сайта.

## Промо-лендинг

- `Button` — основные действия, ссылки и кнопки с иконкой. Уже реализован; отдельный `IconButton` не нужен.
- `Badge` — короткие метки возле названия продукта, возможностей и версий. Уже реализован.
- `Card` — повторяемые блоки с преимуществами и примерами использования.
- `Tabs` — переключение примеров по слоям библиотеки или сценариям использования.
- `CodeBlock` — фрагменты кода; действие копирования собирается из `Button` и `copy()` из `core`, без отдельного `CopyButton`.
- `Accordion` — раскрываемые ответы на частые вопросы, если такой раздел появится.

## Сайт документации

- `Button` — переходы, копирование примеров, отправка и повтор запроса к помощнику. Уже реализован.
- `Input` — строка поиска по документации. Уже реализован.
- `TextArea` — ввод вопроса RAG-помощнику. Уже реализован.
- `Tabs` — варианты одного примера: готовый компонент, адаптер или логика первого слоя.
- `CodeBlock` — примеры установки и использования API.
- `Accordion` — сворачиваемые группы навигации и дополнительные пояснения.
- `Alert` — важные замечания в документации и сообщения об ошибке помощника.
- `Breadcrumb` — положение текущей страницы в структуре документации.

Для поиска с интерактивными подсказками дополнительно понадобится `Listbox` с клавиатурной навигацией; простой поиск может сначала работать без него. `Dialog` нужен только если поиск или помощник открываются поверх страницы, а не встроены в неё.

## Что не является отдельным компонентом библиотеки

Содержимое шапки, hero-блок, секция преимуществ, пункты боковой навигации и окно переписки с помощником собираются в приложениях из библиотечных компонентов и обычной разметки. Сам RAG — получение ответа, поиск по документам и хранение истории — относится к логике сайта, а не к UI-библиотеке. Новые библиотечные компоненты добавляются только там, где появляется повторяемый контракт поведения или оформления, полезный за пределами этих двух сайтов.

## Открытый вопрос

Нужны ли части каркаса как единый составной API (`Layout.Header`, `Layout.Sidebar`, `Layout.Footer`) или как самостоятельные компоненты (`Header`, `Sidebar`, `Footer`)? Решить при проектировании каркаса по его реальным общим правилам; до этого не закреплять форму публичного API.
