# Компоненты библиотеки для лендинга и документации

Здесь перечислены **компоненты Dreadnought**, на которых можно построить промо-лендинг и сайт документации с RAG-помощником. Это план развития библиотеки, а не перечень секций страниц. Готовыми сейчас являются `Button`, `Input`, `TextArea`, `Badge`, `Tabs`, `Card`, `CodeBlock`, `Table`, `Accordion`, `Alert`, `Breadcrumb` и составной `Layout`; остальные пункты — кандидаты, которые реализуются по мере работы над сайтами. Один компонент используется на обоих сайтах без копирования реализации.

## Каркас сайтов

- `Layout.Header` — верхняя область лендинга и документации. Уже реализован.
- `Layout.Content` — основная область страницы. Уже реализован.
- `Layout.Footer` — нижняя область сайтов. Уже реализован.
- `Layout.Sidebar` — боковая область документации со сворачиванием. Уже реализован; навигационные пункты задаёт приложение.

Каркас задаёт переиспользуемую структуру и оформление, но не конкретные логотип, ссылки и тексты сайта.

## Промо-лендинг

- `Button` — основные действия, ссылки и кнопки с иконкой. Уже реализован; отдельный `IconButton` не нужен.
- `Badge` — короткие метки возле названия продукта, возможностей и версий. Уже реализован.
- `Card` — повторяемые блоки с преимуществами и примерами использования. Уже реализован.
- `Tabs` — переключение примеров по слоям библиотеки или сценариям использования. Уже реализован.
- `CodeBlock` — фрагменты кода с необязательным копированием через `copy()` из `core`; уже реализован, отдельный `CopyButton` не нужен.
- `Accordion` — раскрываемые ответы на частые вопросы, если такой раздел появится. Уже реализован.

## Сайт документации

- `Button` — переходы, копирование примеров, отправка и повтор запроса к помощнику. Уже реализован.
- `Input` — строка поиска по документации. Уже реализован.
- `TextArea` — ввод вопроса RAG-помощнику. Уже реализован.
- `Tabs` — варианты одного примера: готовый компонент, адаптер или логика первого слоя. Уже реализован.
- `CodeBlock` — примеры установки и использования API. Уже реализован.
- `Table` — таблицы свойств и другие структурированные данные. Уже реализован.
- `Accordion` — сворачиваемые группы навигации и дополнительные пояснения. Уже реализован.
- `Alert` — важные замечания в документации и сообщения об ошибке помощника. Уже реализован.
- `Breadcrumb` — положение текущей страницы в структуре документации. Уже реализован.

Для поиска с интерактивными подсказками дополнительно понадобится `Listbox` с клавиатурной навигацией; простой поиск может сначала работать без него. `Dialog` нужен только если поиск или помощник открываются поверх страницы, а не встроены в неё.

## Что не является отдельным компонентом библиотеки

Содержимое шапки, hero-блок, секция преимуществ, пункты боковой навигации и окно переписки с помощником собираются в приложениях из библиотечных компонентов и обычной разметки. Сам RAG — получение ответа, поиск по документам и хранение истории — относится к логике сайта, а не к UI-библиотеке. Новые библиотечные компоненты добавляются только там, где появляется повторяемый контракт поведения или оформления, полезный за пределами этих двух сайтов.

Части каркаса объединены в составной API `Layout.*`; отдельные самостоятельные `Header`, `Sidebar` и `Footer` не экспортируются из готовой точки входа.
