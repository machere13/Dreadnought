# Table T1: ключи, фильтры и страницы

Общий контракт `TableAdapter` (слой 2) и `Table` (слой 3).
Core по-прежнему предоставляет существующие `filterTableRows`, `sortTableRows`, `paginateTableRows`; новые универсальные менеджеры состояния не добавляются.

## Ключи строк и миграция

При `rowSelection` каждая запись в `dataSource` должна иметь уникальный устойчивый ключ: поле `record.key`, поле, указанное в `rowKey`, либо результат функции `rowKey(record)`.
Допустимы строки и конечные числа. Число `1` и строка `"1"` конфликтуют, поскольку React преобразует ключи в строки.
Отсутствующие, недопустимые или повторяющиеся ключи вызывают ошибку до отображения таблицы. Автоматических ключей по позиции при выборе строк больше нет: после сортировки они могли выбрать другую запись.

Миграция: если данные содержат `id`, передайте `rowKey="id"`. Не генерируйте ключ из текущей позиции или случайного значения.
Без `rowSelection` индексный запасной ключ остаётся доступен. Для строк с собственным состоянием всё равно нужен устойчивый ключ.
Выбранные объекты возвращаются из текущего `dataSource`, в его порядке; кэширование отсутствующих записей не входит в T1.

## Фильтры и controlled-свойства

- `filteredValue === undefined`: внутреннее состояние фильтра.
- `filteredValue: null` или `[]`: пустой управляемый фильтр, без возврата к default или внутреннему состоянию.
- `defaultFilteredValue`, `defaultSortOrder`, `defaultCurrent`, `defaultPageSize`, `defaultSelectedRowKeys` инициализируют состояние только при создании.
- Управляемые фильтр, сортировка, текущая страница и выбор строк не применяют запрос пользователя до изменения соответствующих props родителем.

## Пагинация

`current`, `pageSize` и начальные значения при их использовании должны быть положительными безопасными целыми числами. Недопустимые значения вызывают `RangeError`, а не молчаливую подстановку.
Размер страницы по умолчанию — 10, страница — 1. Пустые данные имеют одну логическую страницу с пустым состоянием.

- Сортировка сохраняет текущую отображаемую страницу.
- Применение или сброс фильтра запрашивает страницу 1.
- Изменение `pageSize` родителем сбрасывает неуправляемую страницу на 1; управляемый `current` остаётся решением родителя.
- При сокращении данных неуправляемая страница ограничивается последней доступной и сохраняется в состоянии: прежняя страница не возвращается при росте данных.
- Положительный управляемый `current` выше количества страниц ограничивается только для отображения. Prop не исправляется, событий при этом нет. При росте данных его значение снова используется.
- Изменения props и нормализация отображения не вызывают callbacks. Событий изменения размера страницы нет: отдельного пользовательского переключателя размера в T1 нет.

## События

`onChange(pagination, filters, sorter, extra)` получает `extra.action`: `sort`, `filter` или `paginate`.
`extra.currentDataSource` — весь набор после фильтрации и сортировки, до разбиения на страницы. Исходные данные не изменяются.
При управляемых свойствах событие описывает запрошенное изменение, а не прежнее отображение.

При пользовательской фильтрации или переходе страницы сначала один раз вызывается `pagination.onChange`, затем один раз `Table.onChange`.
При сортировке вызывается только `Table.onChange`.
При `pagination={false}` callback пагинации не вызывается.
