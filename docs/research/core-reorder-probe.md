# Проверка core на перестановке списка

Дата: 2026-10-05.

`packages/core/tests/probes/reorder/ReorderProbe.tsx` — тестовая связка одного фиксированного списка Alpha/Beta/Gamma. Это не публичный компонент и не универсальный Drag & Drop. У элементов стабильные ключи; порядок не меняется до подтверждения.

## Распределение ответственности

Core определяет направление клавиши через `getNavigationDirection` и доступную позицию через `getNextEnabledValue` с loop: false. Состояние, drag-события, фокус, текст инструкции и role=status принадлежат React-связке. Перестановка выполняется двумя splice на копии массива: элемент перемещается на индекс выбранной строки в исходном порядке. Перенос на себя ничего не переставляет.

Мышь использует нативный HTML Drag and Drop: draggable, dragstart, dragover, drop, dragend. Разрешается только локальный активный перенос; данные внешнего drop не читаются и не импортируются. Custom MIME не добавляет text/plain для вставки в чужое текстовое поле. Drop использует текущую строку события, а не последнюю hover-позицию. Dragend без подтверждения отменяет сессию; dragend после успешного drop не откатывает результат.

Клавиатура: Space/Enter начинают и подтверждают перенос; стрелки/Home/End выбирают позицию без wrap; Escape отменяет. Повторы стрелок разрешены, повтор Space/Enter не подтверждает случайно. Tab отменяет сессию без preventDefault и без возврата фокуса; уход фокуса тоже отменяет клавиатурный перенос. Disabled блокирует новые события и отменяет активную сессию. Отменённые события, IME и модификаторы не выполняют команду. После подтверждения или явной отмены фокус остаётся на handle перемещаемого элемента.

## Проверки

```sh
node node_modules/vitest/vitest.mjs run packages/core/tests/probes/reorder/ReorderProbe.test.tsx
node node_modules/vite/bin/vite.js packages/core/tests/probes/reorder --config packages/core/tests/probes/dialog/vite.config.ts --host 127.0.0.1 --port 4388 --strictPort
```

Тесты jsdom проверяют порядок, статусы и фокус, подтверждение/отмену, Home/End и границы, внешний drop, Tab, guards, repeat и disabled. Drag-события синтетические, DataTransfer заменён минимальным объектом: это проверка связки, не браузерного drag lifecycle.

В браузере Codex вручную проверены: перенос Alpha в конец клавиатурой с сохранением фокуса; клавиатурный Escape без изменения порядка; реальный перенос Alpha мышью на первую строку; отпускание вне списка с отменой и восстановлением фокуса. Escape во время удержания мыши отдельно не проверен: соответствующая последовательность dragend без drop проверена в jsdom, а нативное правило описано в [MDN: Drag operations](https://developer.mozilla.org/en-US/docs/Web/API/HTML_Drag_and_Drop_API/Drag_operations). Это один браузер, не кросс-браузерная или скринридерная проверка.

## Вывод и границы

Для этого сценария новый API core не нужен: навигация уже общая, а перенос одной записи покрывают стандартные операции массива. Проба не доказывает поддержку любого Drag & Drop. Нет touch/pointer-сенсора, нескольких списков, сетки, геометрии collision detection, автоскролла, виртуализации, нескольких переносимых записей, закреплённых строк, controlled API и обновления данных во время переноса. Такие требования могут потребовать отдельной чистой модели, но оснований публиковать универсальный контроллер по этой пробе нет.
