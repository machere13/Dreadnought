# Проверка core на кастомном Slider

Дата: 2026-10-05.

Проба `packages/core/tests/probes/slider/SliderProbe.tsx` — тестовая связка, не публичный компонент, не готовый дизайн и не часть сборки core. Используется div с role=slider и скрытое поле формы, а не input type=range/number. React хранит значение и связывает DOM-события; core остаётся независимым от React и браузера.

## Выявленная возможность

Публичный `getSteppedValue(value, { min, max, step? })` нормализует числового кандидата к ближайшей точке сетки `min + n * step` внутри диапазона. При равном расстоянии выбирается большая точка. Step по умолчанию 1; min/max обязательны. Если max не лежит на сетке, доступный максимум ниже него. min === max допускается. Нечисловые/неконечные входы вызывают TypeError, min > max или step <= 0 — RangeError.

Внутри используются BigInt и десятичные представления входных number: это предотвращает хвосты вроде 0.30000000000000004 при нормализации к шагу 0.1 и переполнение промежуточной разницы больших границ. Результат — обычный number: потерянные до вызова разряды не восстанавливаются, суб-ULP шаг не гарантирует различные представимые значения. Это не денежная арифметика произвольной точности.

Функция не выполняет команду «прибавить шаг» сама. Потребитель передаёт кандидата — значение плюс/минус step, min/max или результат преобразования координаты. У функции нет DOM, состояния, disabled, события, фокуса и ARIA.

## Композиция

Проба использует getSteppedValue для исходного значения, клавиатурного кандидата и координат. getNavigationDirection определяет стрелки/Home/End; горизонтальное поле также допускает ArrowUp/ArrowDown, с увеличением вверх и вправо. Модификаторы, IME и отменённые события не перехватываются. Геометрия трека и линейный перевод clientX в число принадлежат связке.

Один primary pointer запускает drag, остальные игнорируются. Проба запрашивает native pointer capture и прекращает drag при pointerup, pointercancel, lostpointercapture или уходе фокуса. Отмена не откатывает уже выбранное значение. Нулевая ширина и правая кнопка игнорируются. Disabled блокирует изменения, убирает tab stop и исключает скрытое поле из FormData. ARIA, output и поле формы используют одно нормализованное значение; aria-valuemax отражает последнюю доступную точку. Reset возвращает исходное значение на текущую сетку, отменённый reset сохраняет значение.

## Проверки и границы

Чистые тесты проверяют ближайшую точку, равные расстояния, отрицательные и дробные значения, границы не на сетке, научную запись, очень большие границы, единичную точку, шаг больше диапазона, default step и неверные входы. Сценарии пробы проверяют ARIA/FormData/output, клавиатуру без submit/wrap, дроби, отмену/IME/модификаторы, pointer-события, остановку drag, disabled и reset.

```sh
node node_modules/vitest/vitest.mjs run packages/core/tests/behaviors/getSteppedValue.test.ts packages/core/tests/probes/slider/SliderProbe.test.tsx
```

Проверки пробы выполняются в jsdom с заданной геометрией и MouseEvent, дополненным pointerId/isPrimary. Это проверка реакции связки на события, **не проверка реального hit-testing, pointer capture вне элемента, touch-scroll или скринридера**. Реальные браузеры не проверены. В пробе нет CSS-дизайна, вертикальной/RTL/логарифмической шкалы, нескольких бегунков, PageUp/PageDown, controlled API, callback изменения, динамического переноса в другую форму и наследования disabled fieldset для div. Drag и клавиатура исследованы на небольших конечных диапазонах, не на крайних значениях IEEE-754.

## Вывод

В отличие от нативного NumberField, проба действительно потребовала чистую числовую возможность core. Она опубликована с контрактом и примером в каталоге; UI-поведение остаётся у владельца. Это подтверждает конкретную композицию, не обещание готового Slider или возможности собрать любой компонент без адаптации.
