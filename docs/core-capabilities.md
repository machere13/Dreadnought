# Спецификация возможностей `core`

Этот список задаёт направления развития первого слоя, а не обещает реализовать все пункты сразу. Новая возможность добавляется вместе с конкретным сценарием использования, публичным контрактом и тестами. Границы категорий описаны в [conventions.md](conventions.md).

## Actions — самостоятельные действия

| Возможность | Сценарий | Статус |
|---|---|---|
| `copy(text)` | Копирование текста из любого компонента. | Реализовано |
| `download(blob, filename)` | Скачивание сформированного в приложении файла. | Реализовано; способ очистки временного URL помечен TODO |
| `pickFiles({ accept?, multiple? })` | Выбор файлов для загрузки или обработки. | Реализовано |
| `readClipboard()` | Чтение текста для отдельной команды «Вставить». | Реализовано; разрешение браузера обрабатывает вызывающий код |

Actions не владеют состоянием UI: индикатор загрузки, сообщение об успехе и обработка ошибки остаются у вызывающего кода или хука адаптера. Не добавляем обёртку над браузерным методом без конкретного сценария повторного использования.

## Behaviors — правила без побочных эффектов

| Возможность | Сценарий | Статус |
|---|---|---|
| `getNextEnabledValue` | Переход между доступными пунктами, first/last, круговой переход или остановка на краях; используется Tabs, Select и Menu. | Реализовано |
| `getTypeaheadValue` | Поиск доступного пункта по началу названия без учёта регистра, с круговым обходом. | Реализовано; Menu |
| Изменение значения с ограничениями | Шаг и границы значения для Slider или NumberField. | Кандидат после выбора компонента |
| `getSelectionValue` | Одиночный и множественный выбор, select/deselect/toggle/clear, disabled и required. | Реализовано; Select, Checkbox.Group, Accordion и выбор строк/фильтров Table |

Behavior возвращает результат вычисления, но сам не меняет DOM, не вызывает браузерные API и не навешивает обработчики событий.

`getTypeaheadValue(items, currentValue, query, { includeCurrent? })` получает пункты со строковыми `value` и `text`, пропускает `disabled` и возвращает ключ совпадения или `undefined`. Сравнивает начало названия без учёта регистра и пробелов по краям. Начинает после текущего пункта и обходит коллекцию по кругу; `includeCurrent: true` начинает с текущего, что удобно при уточнении запроса. Неизвестный ключ начинает с первого пункта. Пустой запрос не выбирает пункт. Буфер текста, повторные буквы, время сброса, события, ARIA и фокус — ответственность адаптера. Menu сбрасывает запрос после паузы больше 500 мс, навигации стрелками/Home/End или выхода фокуса из меню; повтор одной буквы перебирает совпадения. Поиск не вызывает действие и не изменяет selectedValue.

`getNextEnabledValue(items, currentValue, direction, { loop? })` возвращает ключ доступного пункта или `undefined`, если доступных пунктов нет. Направления: `previous`, `next`, `first`, `last`; отключённые пункты пропускаются. По умолчанию `loop: true` сохраняет круговой переход (Tabs и Menu); при `loop: false` функция возвращает текущий крайний пункт вместо перехода на противоположный край (Select). Если текущий ключ отсутствует или отключён, `next` начинает с первого доступного пункта, `previous` — с последнего. Определение направления по клавише, отмена события, фокус и ARIA остаются в адаптере: например, Home/End в поисковом поле Select должны двигать текстовый курсор, а не выбор.

`getSelectionValue(current, action, options?)` использует строку/число/null для одиночного выбора и массив для множественного. Возвращает новое значение без изменения входа и убирает дубликаты. `disabled` блокирует все изменения, `disabledValues` блокирует действия над указанными ключами и сохраняет их при `clear`; замена одиночного выбора другим доступным значением разрешена. `required` запрещает удалить последний выбранный ключ, но не выбирает значение автоматически при пустом входе. Доступность и существование ключа в коллекции проверяет вызывающий код. Владение состоянием, события, ARIA и DOM не входят в этот behavior.

## Patterns — контракты доступного взаимодействия

| Возможность | Сценарий | Статус |
|---|---|---|
| Навигация внутри Toolbar | Связать клавиши, фокус и семантику группы элементов. | Следующий кандидат |
| Disclosure | Раскрытие секции с согласованными состоянием и ARIA-связями. | Кандидат |

Паттерн описывает взаимодействие целиком. Независимые правила находятся в `core`, а привязка к DOM, refs и событиям React — в адаптере.

## Domains — специализированные модели

| Возможность | Сценарий | Статус |
|---|---|---|
| Модель Markdown-документа | Редактор с операциями над содержимым. | Кандидат для отдельного этапа |
| Шкалы и геометрия графиков | RadarChart и другие визуализации. | Кандидат для отдельного этапа |

Доменная логика не превращается в универсальный behavior только ради повторного использования внутри одной предметной области.

## Components — контракты конкретных компонентов

`Button` уже имеет контракт состояния в `core`; его поведение и оформление ещё требуют доработки. `Toolbar` — следующий кандидат для проверки композиции actions, behaviors и patterns. `MarkdownEditor` и `RadarChart` остаются проверочными целями архитектуры, но не считаются готовыми компонентами и не требуют заранее создавать пустые папки.
