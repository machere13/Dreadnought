# Спецификация возможностей `core`

Этот список задаёт направления развития первого слоя, а не обещает реализовать все пункты сразу. Новая возможность добавляется вместе с конкретным сценарием использования, публичным контрактом и тестами. Границы категорий описаны в [conventions.md](conventions.md).

Проверка композиции: [кастомный Combobox из публичного core](research/core-combobox-probe.md). Тестовая проба использует поиск, навигацию, выбор и открытие без готового Select. По её результатам выделен `getComboboxKeyAction`; это подтверждение ограниченного сценария, а не готовый компонент библиотеки.

Вторая проверка: [кастомный NumberField](research/core-number-field-probe.md). Для нативного числового поля шаг и ограничения выполняют `stepUp`/`stepDown`, а core предоставляет флаги поля и направление клавиши.

Третья проверка: [кастомный Slider](research/core-slider-probe.md). Числовая сетка вычисляется публичным `getSteppedValue` без нативного range/number input; события и геометрия остаются в тестовой связке.

## Actions — самостоятельные действия

| Возможность | Сценарий | Статус |
|---|---|---|
| `copy(text)` | Копирование текста из любого компонента. | Реализовано |
| `download(blob, filename)` | Скачивание сформированного в приложении файла. | Реализовано; способ очистки временного URL помечен TODO |
| `pickFiles({ accept?, multiple? })` | Выбор файлов для загрузки или обработки. | Реализовано |
| `readClipboard()` | Чтение текста для отдельной команды «Вставить». | Реализовано; разрешение браузера обрабатывает вызывающий код |

Actions не владеют состоянием UI: индикатор загрузки, сообщение об успехе и обработка ошибки остаются у вызывающего кода или хука адаптера. Не добавляем обёртку над браузерным методом без конкретного сценария повторного использования.

## Behaviors — правила без побочных эффектов

| Возможность | Сценарий | Статус |
|---|---|---|
| `getNextEnabledValue` | Переход между доступными пунктами, first/last, круговой переход или остановка на краях; используется Tabs, Select и Menu. | Реализовано |
| `getNavigationDirection` | Преобразование клавиши в направление: горизонтальная/вертикальная навигация, отключаемые Home/End. | Реализовано; Tabs, Menu и Select |
| `getComboboxKeyAction` | Клавиша + open → open/close/select/navigate и решение об отмене нативного действия. | Реализовано; Select и кастомная проба Combobox |
| `getTypeaheadValue` | Поиск доступного пункта по началу названия без учёта регистра, с круговым обходом. | Реализовано; Menu |
| `getDisclosureState` | Согласованные triggerProps/panelProps, ARIA-связи и hidden с ID владельца. | Реализовано; Accordion и пример собственной секции |
| `getDisclosureOpen` | Следующее open по open/close/toggle; disabled блокирует запрос, не закрывая секцию. | Реализовано; пример собственной секции |
| `getSteppedValue` | Привязка кандидата к ближайшей точке сетки с шагом и границами. | Реализовано; кастомная проба Slider. Нативный NumberField продолжает использовать stepUp/stepDown |
| `getSelectionValue` | Одиночный и множественный выбор, select/deselect/toggle/clear, disabled и required. | Реализовано; Select, Checkbox.Group, Accordion и выбор строк/фильтров Table |

Behavior возвращает результат вычисления, но сам не меняет DOM, не вызывает браузерные API и не навешивает обработчики событий.

`getComboboxKeyAction(key, { open, searchable?, openOnEnter? })` возвращает действие с `preventDefault` либо `undefined`. По умолчанию searchable/openOnEnter — true: Enter открывает закрытый список или выбирает в открытом; `openOnEnter: false` оставляет закрытый Enter форме. Escape закрывает открытый список и запрашивает отмену события; Tab закрывает без отмены, сохраняя переход фокуса. ArrowUp/ArrowDown возвращают navigate с previous/next. При searchable: false Space активирует и Home/End навигируют; иначе эти клавиши остаются текстовому вводу. Владелец проверяет disabled, отмену события, IME, модификаторы и доступность активного пункта; затем выполняет действие, preventDefault и фокус. Behavior не является обработчиком DOM и не хранит состояние.

`getNavigationDirection(key, { orientation?, homeEnd? })` принимает строку клавиши и возвращает `previous`, `next`, `first`, `last` или `undefined`. По умолчанию ориентация вертикальная (ArrowUp/ArrowDown), Home/End включены. Горизонтальная ориентация использует ArrowLeft/ArrowRight; противоположная пара стрелок игнорируется. `homeEnd: false` оставляет Home/End текстовому курсору, как в поисковом Select. Функция не определяет RTL, модификаторы и IME и не получает DOM-событие: проверку события, `preventDefault`, фокус и выбор обеспечивает адаптер. Для определения следующего ключа результат передаётся в `getNextEnabledValue`. Не меняем публичные пропсы компонентов и их текущую ориентацию: Tabs остаётся горизонтальным, Menu и Select — вертикальными.

`getTypeaheadValue(items, currentValue, query, { includeCurrent? })` получает пункты со строковыми `value` и `text`, пропускает `disabled` и возвращает ключ совпадения или `undefined`. Сравнивает начало названия без учёта регистра и пробелов по краям. Начинает после текущего пункта и обходит коллекцию по кругу; `includeCurrent: true` начинает с текущего, что удобно при уточнении запроса. Неизвестный ключ начинает с первого пункта. Пустой запрос не выбирает пункт. Буфер текста, повторные буквы, время сброса, события, ARIA и фокус — ответственность адаптера. Menu сбрасывает запрос после паузы больше 500 мс, навигации стрелками/Home/End или выхода фокуса из меню; повтор одной буквы перебирает совпадения. Поиск не вызывает действие и не изменяет selectedValue.

`getNextEnabledValue(items, currentValue, direction, { loop? })` возвращает ключ доступного пункта или `undefined`, если доступных пунктов нет. Направления: `previous`, `next`, `first`, `last`; отключённые пункты пропускаются. По умолчанию `loop: true` сохраняет круговой переход (Tabs и Menu); при `loop: false` функция возвращает текущий крайний пункт вместо перехода на противоположный край (Select). Если текущий ключ отсутствует или отключён, `next` начинает с первого доступного пункта, `previous` — с последнего. Определение направления по клавише, отмена события, фокус и ARIA остаются в адаптере: например, Home/End в поисковом поле Select должны двигать текстовый курсор, а не выбор.

`getSelectionValue(current, action, options?)` использует строку/число/null для одиночного выбора и массив для множественного. Возвращает новое значение без изменения входа и убирает дубликаты. `disabled` блокирует все изменения, `disabledValues` блокирует действия над указанными ключами и сохраняет их при `clear`; замена одиночного выбора другим доступным значением разрешена. `required` запрещает удалить последний выбранный ключ, но не выбирает значение автоматически при пустом входе. Доступность и существование ключа в коллекции проверяет вызывающий код. Владение состоянием, события, ARIA и DOM не входят в этот behavior.

## Patterns — контракты доступного взаимодействия

| Возможность | Сценарий | Статус |
|---|---|---|
| Навигация внутри Toolbar | Связать клавиши, фокус и семантику группы элементов. | Реализовано; контракт core и React-адаптер, roving/native |
| Disclosure | Раскрытие секции с согласованными состоянием и ARIA-связями. | Базовые behaviors реализованы; состояние, события и фокус — у владельца |

Паттерн описывает взаимодействие целиком. Независимые правила находятся в `core`, а привязка к DOM, refs и событиям React — в адаптере.

`getDisclosureState({ open?, disabled?, triggerId, panelId })` не генерирует ID: владелец задаёт непустые разные ID без ASCII whitespace и обеспечивает уникальность на странице. По умолчанию open/disabled — false. `getDisclosureOpen(currentOpen, action, { disabled? })` принимает open/close/toggle; disabled сохраняет текущее значение. Внешний controlled-владелец может закрыть секцию независимо от disabled. Пример в документации использует нативную кнопку, mounted hidden-панель и возвращает фокус только при закрытии с фокусом внутри неё. Общего controller или popup API нет.

Уточнение Disclosure: невалидное действие из JavaScript вызывает TypeError, включая disabled-режим. В каталоге варианты action опубликованы структурированно в parameters[].values, defaults options — в parameters[].defaults. Accordion восстанавливает фокус в документе самой панели, включая iframe/React portal, и не перехватывает фокус из родительской страницы.

## Domains — специализированные модели

| Возможность | Сценарий | Статус |
|---|---|---|
| Модель Markdown-документа | Редактор с операциями над содержимым. | Кандидат для отдельного этапа |
| Шкалы и геометрия графиков | RadarChart и другие визуализации. | Кандидат для отдельного этапа |

Доменная логика не превращается в универсальный behavior только ради повторного использования внутри одной предметной области.

## Components — контракты конкретных компонентов

`Button` уже имеет контракт состояния в `core`; его поведение и оформление ещё требуют доработки. `Toolbar` реализован и проверяет композицию behaviors и взаимодействия с собственными элементами. `MarkdownEditor` и `RadarChart` остаются проверочными целями архитектуры, но не считаются готовыми компонентами и не требуют заранее создавать пустые папки.
