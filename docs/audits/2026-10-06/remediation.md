# Исправления аудита Dreadnought

Исходный отчёт: [dreadnought-audit.md](dreadnought-audit.md). Его выводы сохранены как история проверки, а не переписаны задним числом.

## Исправлено

- D01/D02: Tabs и Menu оставляют клавиши методу ввода при composition.
- D03: Select доставляет invalid через настоящий input, поэтому target/currentTarget соответствуют публичному типу. Основной callback и callback control-слота вызываются; preventDefault отменяет внутренний перевод фокуса. Ошибка валидации при этом остаётся видимой.
- D04: явно заданные aria-label/aria-labelledby popup-слота имеют приоритет перед подписью Select; обязательная семантика списка остаётся у библиотеки.
- D05: Select, Checkbox.Group и Radio.Group переподписываются при смене form. Старая форма больше не сбрасывает новое поле; отменённый reset сохраняет состояние.
- D06: локальный Accordion вычисляет следующие переходы из ожидающего значения, а не устаревшего снимка рендера. Callbacks не находятся внутри state updater. Controlled-значение остаётся у владельца.
- D07: Select снимает внутреннюю ошибку после изменения значения или ограничений, если нативный select теперь валиден. Внешний invalid не снимается.
- D08/M04: TextArea и Accordion переиспользуют attachRef; cleanup пользовательского ref сохраняется при замене и размонтировании.
- M01: переменные оформления TextArea устанавливаются только в UI-фасаде; адаптер сохраняет функциональную геометрию autoSize и метаданные bounds.
- M03: указанные внутренние импорты таблицы и графиков используют конкретные файлы вместо публичных реэкспортов. Type-only импорт IconName через публичный вход сохранён: внутренний #presentation-алиас переносится в декларации и указывает на src, который не входит в публикуемый пакет. Это исключение сохраняет доступность публичных типов; runtime-зависимость этим импортом не создаётся.

## Продолжение проверки

- M02: отображение Table и currentDataSource в onChange используют одну чистую функцию matchingRows с существующими filter/sort из core. Публичный API и геометрия таблицы не менялись.
- M05: добавлен браузерный стенд с десятью проверками фактического computed style. Проверены Roboto Flex, размер/вес/высота строки кнопки, вариативная ширина только у заголовка/кнопки, её отключение через configureDreadnought, вложенный токен и обычный потребительский CSS поверх @layer без !important. Проверки прошли с включённой и отключённой шириной. Стенд запускается отдельно, не является автоматическим CI-браузерным runner.
- R01: определён и проверен контракт актуальной подписки. CodeBlock использует последний committed callback при завершении успеха/ошибки; текст операции остаётся её снимком. Защита при смене code и unmount сохранена. Контракт добавлен в каталог.
- R02: в реальном in-app Chromium проверен useAnchoredPopover под StrictMode с повторной заменой anchor при открытом popup. React open и :popover-open оставались true; браузер объединял hide/show в open→open. Обычный внешний клик дал open→closed и корректно снял React open. Дефект в этом сценарии не воспроизведён; реализация popover не изменялась. Это не доказательство для всех браузеров и последовательностей взаимодействия.
- R03: у Line/Bar/Radar подтверждена потеря двух изменений легенды до commit. Общий React-хук useSeriesVisibility сохраняет ожидающие локальные переходы, controlled-значение владельца, мемоизацию видимого массива и изоляцию от мутации callback. В Table подтверждена потеря составного применения двух фильтров в fallback-режиме; pending-снимок сохраняет оба фильтра и согласованный payload. Составной выбор строк Table прошёл без исправления — этот риск не объявляется дефектом.

Регрессии продолжения: `packages/adapters/react/tests/audit/remainingRisks.test.tsx`. Первоначально наблюдались пять сбоев (два callback и три графика), затем отдельно красный сценарий двух фильтров. После исправлений все 11 проверок проходят.

Итоговый общий прогон: 127 файлов, 835 тестов — все прошли. Проверка типов workspace и сборка React-адаптеров также прошли.

## Браузерный стенд

```powershell
pnpm --filter @dreadnought/react build
pnpm --filter @dreadnought/ui build
node node_modules/vite/bin/vite.js packages/adapters/react/tests/audit/browser --host 127.0.0.1 --port 4397 --strictPort
```

Открыть http://127.0.0.1:4397/. После начального open дважды нажать Replace anchor и Check popover: React open и Popover invariant должны быть true. Затем Check computed styles: passed=true и failures=[]. Нажать Toggle wide typography и снова Check computed styles: passed=true, heading/button variation=normal. Внешний клик при проверке CSS должен закрыть popover. StrictMode включён в стенде. Если popover не поддерживается браузером, этот сценарий нельзя считать проверкой нативного top layer.

Неподтверждённые риски не объявлены исправленными. Системный IME и экранный диктор этими тестами не проверяются; браузерный top layer проверен только в явно описанном сценарии.
