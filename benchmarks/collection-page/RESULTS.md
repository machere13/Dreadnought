# CollectionPage: промежуточная проверка

2 октября 2026. После неудачного чистого прогона v6 добавлен `CollectionPage`: один публичный контракт для локального списка с поиском, фильтром статусов, счётчиками, таблицей и формой создания. Исходный [протокол v6](../token-comparison-v6/PROTOCOL.md) и его [результат](../token-comparison-v6/RESULTS.md) не менялись.

## Что измерено

При одинаковом `--project apps/docs --max-bytes 32768` ответ локального каталога для `CollectionPage` занимает 3028 байт UTF-8, а пакетный ответ для `Button,Input,Card,Badge,Tabs,Table` — 7875 байт. Оба ответа полные (`truncated: false`). Уменьшение выдачи каталога — 61,5%. Это **байты ответа**, не токены модели и не время реализации.

Проверка воспроизводится командами:

```powershell
node tools/catalog/src/query.mjs context --components CollectionPage --project apps/docs --max-bytes 32768
node tools/catalog/src/query.mjs context --components Button,Input,Card,Badge,Tabs,Table --project apps/docs --max-bytes 32768
```

Сценарий проходит тесты фильтрации, счётчиков, поиска и создания записи; сборку и проверку типов. Он рассчитан на локальное состояние. Серверные данные, асинхронное создание и управляемое состояние в этот контракт не входят.

## Что пока не доказано

Нового независимого агентского прогона с тем же заданием и замером входных/выходных токенов **не было**. Поэтому нельзя утверждать, что `CollectionPage` уже сократил суммарные токены или время работы относительно React/CSS. Для этого нужен новый чистый прогон по протоколу v6 с единственным изменением: агенту с библиотекой доступен `CollectionPage` и актуальный каталог.
