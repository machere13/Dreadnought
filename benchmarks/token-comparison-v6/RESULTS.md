# Чистый прогон v6: Dreadnought против React/CSS

2 октября 2026. Условия и критерии корректности записаны в [PROTOCOL.md](./PROTOCOL.md) до запуска. Два независимых агента `gpt-6-sol` получили одно задание на экран «Командная доска» в новых пустых React/TypeScript-проектах. Оба использовали `ponytail`; агент с библиотекой дополнительно использовал обновлённый Dreadnought-скилл и локальный MCP-каталог. Стартовые `src` содержали только `main.tsx` без импорта CSS; имя файла и способ организации стилей не задавались. Старые реализации и результаты агентам читать запретили.

В этом прогоне собственный код с Dreadnought оказался на **12,1% короче**, но метрика «вход без кеша + выход» — на **71,0% выше**. Все входные и выходные токены вместе — на **121,9% выше**. Это результат одного прогона, а не статистическая оценка и не денежная стоимость: кешированные токены тоже могут тарифицироваться, но иначе.

Критерий корректного использования готового третьего слоя **пройден в итоговой реализации**: используются публичные Button, Input, Card, Badge, Tabs и Table; стили приложения находятся в CSS Module; глобальный CSS — только reset; нет `!important`, назначения компонентных токенов или переоформления внутренних селекторов библиотеки. При независимой проверке сначала обнаружились три селектора, привязанные к внутренней разметке Input/Table только для ширины. Тот же агент исправил их через публичный `className`; токены этой дополнительной правки включены в итоговые числа. Код scratch-агента не менялся.

Агент Dreadnought сделал два MCP-вызова: первый получил `spawn EPERM` в песочнице, второй успешно вернул пакетный `context` для шести компонентов и подтверждение совместимости. Дополнительных `get`/`check` не было. Первый запуск сборки у агентов также сталкивался с `spawn EPERM`; повтор с разрешением прошёл. Эти диагностические шаги входят в агентский расход, так что разницу нельзя целиком приписать работе с API каталога.

Независимый общий smoke-тест проверил, что исходная задача отображается, новая добавляется через форму, а поиск показывает пустое состояние; обе реализации прошли. В первой версии теста точное совпадение подписи не принимало корректную подпись «Название задачи *». Тест исправлен на совпадение по началу доступного имени и повторно пройден; исходный код агентов для этого не менялся. Визуальное качество, работа всех вкладок и полная доступность автоматическим тестом не оценивались.

Метрики взяты из последних `thread_token_usage` журналов двух агентов; у Dreadnought они включают продолжение после независимой проверки. Байты собственного кода — `App.tsx` и CSS-файлы в `src`. Размеры сборок — вывод повторной production-сборки. Подготовка проектов, независимый тест и написание этого отчёта в агентский расход не включены.
