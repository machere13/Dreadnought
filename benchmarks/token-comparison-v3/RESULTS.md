# Сравнение токенов после компактного MCP-запроса

Дата: 2 октября 2026. Два новых независимых агента на `gpt-6-sol` без истории прежних benchmark-прогонов получили одинаковое ТЗ на экран «Командная доска». Стартовые React 19 / TypeScript 5.9 / Vite 7 проекты собраны до запуска агентов, зависимости установлены заранее. Оба применяли `ponytail`. Один использовал готовые компоненты Dreadnought и локальный MCP, второй — React/HTML/CSS без UI-библиотеки. Агентам запретили читать прошлые реализации и результаты.

| Показатель | Dreadnought + компактный MCP | React + CSS |
| --- | ---: | ---: |
| Входные токены, всего | 725 169 | 468 890 |
| Из них кешированные | 660 224 | 449 280 |
| Входные без кеша | 64 945 | 19 610 |
| Выходные токены | 13 521 | 12 775 |
| Входные без кеша + выходные | **78 466** | **32 385** |
| Все токены, включая кеш | 738 690 | 481 665 |
| Собственный `App.tsx` + `style.css`, байт | 17 408 | 18 305 |
| JS production build, gzip | 85,13 КБ | 72,07 КБ |
| CSS production build, gzip | 13,49 КБ | 2,97 КБ |
| Production build | прошёл | прошёл |
| Smoke-тест добавления и поиска задачи | прошёл | прошёл |

**Наблюдение одного прогона:** вариант с Dreadnought показал в **2,42 раза больше** некешированных входных и выходных токенов. Но это число нельзя целиком приписывать библиотеке: в начале прогона условия кеширования оказались разными. Его собственный код (`App.tsx` + `style.css`) на 4,9% меньше, а выходных токенов почти поровну: 13 521 против 12 775.

### Что исказило сравнение

В первых двух ответах модели агент с Dreadnought получил 42 281 некешированный входной токен, агент без библиотеки — 4 011. При этом **всего входных токенов** в этих же двух ответах у первого было *меньше*: 68 521 против 77 995. Разница некешированного ввода возникла главным образом из-за разного попадания в кеш, а не из-за размера каталога. Эти первые два ответа дали 38 270 из 45 335 токенов разницы некешированного ввода — **84,4%**. Поэтому опубликованное отношение 2,42 нельзя трактовать как чистую стоимость Dreadnought.

Для контроля: в предыдущем v2 первые два ответа дали 5 492 против 4 149 некешированных токенов. Настолько сильного перекоса кеша там не было, но v2 и v3 всё равно нельзя напрямую сравнивать как измерение одной переменной.

После первых двух ответов осталось 22 664 против 15 599 некешированных входных токенов. Это тоже не чистый эксперимент: действия агентов различались. По сумме **всех** входных и выходных токенов, независимо от кеша, получилось 738 690 против 481 665 (в 1,53 раза больше). Эта разница отражает прежде всего большее число шагов и повторное прохождение уже накопленного контекста.

MCP использован фактически: успешные `check`, один `context` для Button, Input, Card, Badge, Tabs и Table, затем точечный `get` свойства Table.columns. Компактный ответ для шести компонентов составил 7 880 UTF-8 байт и не был обрезан. До успешных вызовов одна попытка `check` завершилась ошибкой запуска дочернего процесса в песочнице; она тоже вошла в токены агента. Агент не читал исходники библиотеки, её документацию или весь `catalog.json`.

По журналам у агента с библиотекой было 14 инструментальных вызовов и 15 ответов модели против 8 и 10 у React/CSS. Дополнительные шаги: чтение Dreadnought Skill, повтор `check` после ошибки песочницы, `context`, точечный `get` Table.columns, проверка манифестов пакетов и дополнительная инспекция кода. Суммарный текст ответов инструментов — около 34,7 тыс. против 12,4 тыс. символов. Ответ `context` сам по себе мал; лишние циклы заставили модель повторно обрабатывать накопленный контекст. Вклад каждого шага отдельно не измерялся.

После работы агентов обе сборки повторно прошли `pnpm run build`. Общий smoke-тест проверил наличие исходных задач, добавление задачи через форму и пустое состояние поиска. Он не оценивает визуальное качество, все варианты клавиатурной навигации и каждую ветвь фильтров.

Числа взяты из последних `token_usage_record.thread_token_usage` журналов двух агентов. Кешированный ввод показан отдельно; сумма «вход без кеша + выход» не равна денежной стоимости API. Подготовка проектов и проверки после завершения агентов в эти числа не входят. Это один прогон, не статистическая оценка; сравнение с предыдущим v2 не изолирует эффект каталога, поскольку реализации и работа агентов получились другими. **Уменьшение выдачи каталога не привело к меньшему общему числу обработанных токенов в этом прогоне; величину влияния самой библиотеки на некешированный расход этот тест не определил.**
