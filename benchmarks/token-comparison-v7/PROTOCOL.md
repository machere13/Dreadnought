# Чистый прогон v7 — зафиксирован до запуска

3 октября 2026. Сравниваем расход двух независимых агентов на одинаковый экран «Командная доска». Оба агента стартуют без истории (fork_turns=none), с одной унаследованной моделью и настройками. У них новые проекты и одинаковые React/TypeScript/Vite. Старые реализации и отчёты читать запрещено. Это инструкционная изоляция, не отдельные машины.

Библиотека заморожена: установлены архивы от 2 октября, использованные в v6. CollectionPage в них отсутствует и удалён из экспериментального снимка каталога. Изменения библиотеки запрещены. Эксперимент v7 проверяет короткий входной скилл и пакетное получение API существующих компонентов через настоящий MCP-сервер. Полный каталог остаётся источником ответа; готового кода экрана агенту не дают.

Задание обоим: тёмный графитовый адаптивный экран, шапка с «Новая задача», боковая навигация, три счётчика (всего / в работе / готово), поиск, четыре вкладки (все и три статуса), таблица из четырёх столбцов, бейджи статусов, модальная форма создания с обязательными названием и исполнителем, статусом и приоритетом. Поиск и статус фильтруют совместно; счётчики относятся ко всему списку. После создания сбрасываются фильтры, новая запись видна, счётчики обновлены. Пустое состояние. Подписанные поля, клавиатурные вкладки и закрытие диалога по Escape. При 360px страница не расползается; таблица может прокручиваться внутри. Хранилище локальное, сервер не нужен. Дополнительные страницы и функции не нужны.

Сначала ведущий устанавливает зависимости и проверяет обе сборки, чтобы одинаковая подготовка не попадала в расход агентов. Оба читают ponytail, реализуют экран и запускают production build. Агент библиотеки дополнительно читает экспериментальный SKILL.md и использует существующие Button, Input, Card, Badge, Tabs, Table; недостающие примитивы — HTML. Нельзя переписывать внутренний дизайн компонентов. Любые исправления после общей проверки делает тот же агент; их токены и время включаются.

Основная метрика как в v6: входные токены без кеша + выходные из последнего thread_token_usage. Также публикуются весь вход, кешированный вход, выход, суммарные токены, число ответов/инструментов и время от первого запроса до последнего ответа. Сравнение по меньшим байтам или строкам кода не заменяет токены. Все попытки сохраняются, неудачные не удаляются. Один выигрыш не доказывает статистическую устойчивость или универсальную экономию.

Перед признанием выигрыша: обе сборки, одинаковые функциональные проверки поиска/статусов/счётчиков/создания/пустого состояния/валидации и проверка публичных импортов/стилей библиотечного варианта. Визуальную проверку выполняет ведущий отдельно. Полные функциональность и читаемость обязательны; минификация исходников не является оптимизацией.
