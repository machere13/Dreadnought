# Повторный тест расхода токенов

2 октября 2026. Два независимых агента на `gpt-6-sol` получили одинаковое задание на экран «Командная доска» и чистые React/TypeScript/Vite-проекты. Оба использовали `ponytail`. Один работал с Dreadnought и обновлённым локальным MCP-каталогом, второй — с React/HTML/CSS без UI-библиотеки. Старые реализации и результаты агентам читать запретили. Подготовка проектов и независимые проверки после завершения агентов в их расход не включены.

| Показатель | Dreadnought | React/CSS |
| --- | ---: | ---: |
| Входные токены, всего | 416 790 | 348 201 |
| Из них кешированные | 398 208 | 335 104 |
| Входные без кеша | 18 582 | 13 097 |
| Выходные токены | 7 822 | 6 853 |
| Входные без кеша + выходные | **26 404** | **19 950** |
| Все входные + выходные | **424 612** | **355 054** |
| Вызовы инструментов агента | 8 | 7 |
| Собственные `App.tsx` + `style.css`, байт | 18 750 | 17 032 |
| Production JS, gzip | 85,32 КБ | 71,74 КБ |
| Production CSS, gzip | 9,80 КБ | 2,62 КБ |
| Production build | прошёл | прошёл |
| Общий smoke-тест | прошёл | прошёл |

В этом прогоне вариант с Dreadnought затратил на **19,6% больше всех токенов** и на **32,4% больше некешированного ввода вместе с выводом**. Собственный код оказался на 10,1% больше. Это наблюдение одного прогона, а не статистическая оценка эффекта библиотеки или денежной стоимости.

**Ограничение результата:** агент с Dreadnought нарушил правила применения третьего слоя. В `src/style.css` у него 49 `!important`: он напрямую переоформил Card, Input, Tabs, Table, Badge и Button вместо использования готовой темы и публичных токенов. Стили приложения записаны в глобальный CSS, а не в CSS Modules. Поэтому этот прогон измеряет стоимость борьбы с готовым оформлением, а не расход при правильном применении фреймворка. Цифры сохранены как факт запуска, но делать по ним вывод «Dreadnought увеличивает расход токенов» нельзя.

Исправленный сценарий каталога действительно сократил путь: агент сделал один успешный `context` для шести компонентов, получил `compatible` и пример составной Table; отдельных `check`, `get` и чтения манифестов не было. Первая попытка MCP-запроса столкнулась с `spawn EPERM` песочницы и была повторена с разрешением. У агента с библиотекой также была одна синтаксическая ошибка в вызове инструмента. Первая сборка у обоих агентов столкнулась с `spawn EPERM`, затем сборки прошли. Эти случайные дополнительные шаги входят в токены и не позволяют приписать всю разницу API библиотеки.

В отличие от предыдущего прогона, начальное кеширование не было перекошено против Dreadnought: в первых двух ответах некешированный ввод составил 2 583 против 4 016 токенов. Поэтому прежнее объяснение аномалии кешем здесь не подходит. Агент с библиотекой сделал больше шагов и написал больше CSS, включая переоформление готовых компонентов. Причинный вклад каждого фактора отдельно не измерялся.

Независимая проверка после работы агентов повторила `pnpm run build` для обоих проектов и общий smoke-тест: исходная задача видна, новая задача добавляется через форму, поиск показывает пустое состояние. Оба теста прошли. Визуальное качество и все ветви доступности этим тестом не оцениваются.

Цифры токенов взяты из последних `thread_token_usage` журналов двух агентов текущего прогона; отменённый до начала работы пробный агент в расчёт не входит. Числа файлов — UTF-8 байты `App.tsx` и `style.css`. Размеры сборок — вывод Vite после повторной сборки. Сравнивать проценты v4 и v3 как изолированный эффект одной правки нельзя: реализации и поведение агентов различались.
